Answer actions

BuildingOptionalMain area

What a reader can do with a finished answer: copy it with its sources, copy the link to its thread, and say whether it was useful.

UI name
«Kopier svaret», «Kopier lenke til tråden», «Var svaret nyttig?»
Sits in
The last row of the answer
Issue
kunnskapsassistenten#224
Code
AnswerActions in packages/ui-blocks

Use it when

  • Readers take answers elsewhere: into a document, an email or a case.
  • The service wants to learn which answers help, and why not.

Don't use it when

  • The answer is not finished. There is nothing to copy from half an answer, so the app draws no row until the answer is done.

Variants

  • Copy, as in kunnskapsassistenten: «Kopier svaret» and «Kopier lenke til tråden», with when the answer came at the far end.
  • Feedback, as in genki's workspace: «Var svaret nyttig?» with «Ja» and «Nei», then reasons for a no, a comment, «Send» and «Hopp over». Off unless the app asks for it with feedback: kunnskapsassistenten took the feedback under each answer out on 6 October 2026, because it adds a lot of noise under every answer, and has it to be rethought.
  • Both, the copy row first and the feedback under a rule.

Each copy button is drawn only when the app passes its event, the feedback only when it also passes feedback, and the block draws nothing when it has none.

The answer block's answerCopy gives the text for «Kopier svaret» with its reference list, and the count for the receipt.

Props

The block raises events. The app copies, sends, and passes back what happened.

  • onCopyAnswer and onCopyLink: the reader asked to copy. copied is the receipt: { kind: 'answer', sources }, { kind: 'link' } or { kind: 'failed' }. A new object for each copy; the receipt clears itself after four seconds.
  • linkOnlyHere: the link opens the thread only for this person, in this browser, and the block says so.
  • feedback and onFeedback: the form, off by default, and { rating, reasons, comment }, the platform's feedback without the task id, which the app adds. feedbackStatus is 'sending', 'sent' or 'failed'.
  • actions: the app's own buttons after the copy buttons. end: what sits at the far end, such as when the answer came.
  • color: Designsystemet's data-color, set only when given.

Related

  • Chat: the row closes each answer
  • Footnotes: the copied answer keeps its numbers
  • Sources: the copied answer lists them under it

Branding

A brand is a Designsystemet theme. The block sits in @layer genai.components, after Designsystemet's layers, follows data-color, data-color-scheme and data-size, and reads every token through its own variable, with the token as the fallback. Set one on any ancestor to change that detail only. Eight are pinned to neutral on purpose, as kunnskapsassistenten and the workspace draw them: the helper text, the rule above the feedback, and the form's ground and field.

What we have learned

  • An answer must not leave the service without where it came from. In kunnskapsassistenten, «Kopier svaret» copies the answer with its numbers and the sources under it, and the receipt counts them: «Svaret og 3 kilder er kopiert.». What goes on the clipboard is the app's; the block shows the count it gets.
  • In kunnskapsassistenten, a thread's link opens it only in the browser it was made in (kunnskapsassistenten#119). The limit is the button's description, not its name, so the row keeps its height; the tooltip, the description and the receipt say the same sentence.
  • The receipt is a polite live region that is always in the page, even empty. A region and its text that arrive in the same frame announce nothing. It scrolls into view as little as it must, and a focus ring a keyboard user sees stays in view too.
  • Feedback is stored for the service, not for the person, and the form says so after «Send». The comment is at most 300 characters and asks for no personal data.
  • The reasons are sent in bokmål whatever language the person reads, as the workspace stores them, so the service reads them the same way.

What is built

  • Designsystemet Buttons, tertiary and small, with the clipboard icons, as in kunnskapsassistenten. Tooltip for the link's limit.
  • Feedback as in the workspace: «Ja» and «Nei» are toggle buttons with aria-pressed, a Fieldset of Chip checkboxes for a no, a Textarea with its count, and a status line.
  • While the app sends, «Send» shows that it is busy and nothing is sent twice. When it is sent, the form closes and the rating can't be changed. When it failed, the form stays for another try.
  • The block never calls the platform; tests check that it copies and sends nothing.

Open questions

  • Should kunnskapsassistenten ask for feedback again, and where? It took the link under each answer out on 6 October 2026, to be rethought; the block keeps the form behind feedback.
  • Should an answer opened again show the rating already given? The block can only show what the app passes in.
