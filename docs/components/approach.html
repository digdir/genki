Use it when

  • Users need to see what the assistant did, and what the answer is based on.
  • The assistant has a filter that can change between questions.

Variants

  • A, card above the answer: can be collapsed and expanded. A4 has the filter for each answer inside the card.
  • B, in the tools panel: as one of the tools.
  • What is missing: a section of its own (A3, A3b).

Props

  • steps: the steps in order. A run of steps with the same title one after another is one line with a count, «Leste de relevante delene nøye (4 ganger)». The same step again after another one is a line of its own.
  • working, startedAt and finishedAt: while it works, and when it started and finished, in milliseconds since the epoch.
  • read and used: the documents read and the sources used, for the line at the bottom once the answer is done.
  • open and onOpenChange: a host that keeps the card open or shut passes open, and hears through onOpenChange when the person opens or shuts it. Without open the card keeps its own state: open while it works, shut when the answer is done, and as the person left it.
  • onShowRead and onExplainMissing: the links «Vis de 17 som er lest» and «Utdyp hva som mangler», shown only when the app can open them.

A step

  • id, title and status: done, active or waiting.
  • description: a line under the title.
  • documents and documentsRead: the first documents the step read, with where in them, and how many it read in all.
  • excerptsRead: the excerpts the step read closely. A run of such steps adds them up, and its line says «Leste 12 utdrag nøye» in place of the title.
  • sourcesUsed: the source numbers the answer used.
  • missing: the step says what the assistant did not find.

Related

  • Chat: sits above the answer, or in the panel beside it
  • Filter: shows the filter used for each answer
  • Sources: the steps show which sources were used

Branding

A brand is a Designsystemet theme. The block sits in @layer genai.components, after Designsystemet's layers, follows data-color, data-color-scheme and data-size, and reads every token through its own variable, with the token as the fallback. Set one on any ancestor to change that detail only. The grey lines are pinned to neutral, as kunnskapsassistenten draws them. Its words are in its own catalogue, approach, so a host that imports Approach alone loads no other block's.

What we have learned

  • Hypothesis: A4 works best. It allows for the filter changing, and the placement feels natural.
  • Collapsed, the card is one line, for example «Leste 44 dokumenter, brukte 4». The line says «filteret er endret» only when it has changed.
  • The filter choices are shown as identical chips without borders or emphasis, and can't be clicked. Changes are made only in the filter.
  • The source trail is a compact strip that can be opened step by step.
  • Can be added later: a line saying what changed in the filter since the previous answer, for example «+ Tilsynsrapport».

What is built

  • Variant A, the card above the answer: Designsystemet Card with Details and a numbered List, the robot icon and «Fremgangsmåte». No subtitle.
  • Open while the assistant works, closed when the answer is done. If the person closes it while the assistant works, it stays closed. It can be opened again. A host that passes open keeps it open or shut instead.
  • A run of the same step one after another is one line with a count, «Lette etter steder som handler om spørsmålet (2 ganger)», or, for a reading run that knows its excerpts, «Leste 12 utdrag nøye».
  • Each step is done, in progress or waiting. The status is always text: «· pågår» and «· venter» are visible, «ferdig» is for screen readers. The step in progress has aria-current="step". A step that waits shows only its title.
  • One polite live region says «Steg 4 av 7: …» when the step in progress changes, without reading the list again.
  • The bottom line counts seconds while it works («Har jobbet i 18 sekunder»), then says what it read and used and how long it took.
  • A step can list documents with pages, link to everything it read, and say which sources the answer used. The link is shown only when the app can open it.
  • The steps come from the platform, never from the component. The workspace asks for genai_steps, shows a label as sent, and translates the tool names it knows (plan_queries, inspect_filters, search, read_chunks, rerank_results, report_gaps, generate_response) in the person's language, also after a switch. Frames a person cannot read are left out, a tool called again in a row stays one step, and there is no card without steps.

What the platform does not send yet

  • Today only services that search with tools send steps a person can read, and only the tool name. Services with a fixed retrieval flow send none, so they show no card.
  • Until the platform sends more, the workspace's example data shows the whole card, with the text from the design, so it can be seen and tested in full.
  • Where «Vis de 38 som ble lest» and «Utdyp hva som mangler» lead is not designed yet, so the workspace shows neither link.

Proposed step frame

What the card needs in each genai_step frame, on top of tool and label. The workspace reads these already (apps/workspace/src/procedure.ts); the platform needs to send them.

  • plan: the tool names of every step the run will take, in the first frame, so the ones not reached show as waiting.
  • description: one or two sentences under the title.
  • documents: { title, pages } for the documents a step read closely, the first few.
  • documents-read: how many the step has read so far.
  • documents-total: how many documents the run reads from, for the line at the bottom.
  • sources-used: the source numbers the answer used.
  • missing: the step says what was not found. The workspace titles a tool named report_gaps as this step; no strategy has that tool yet.

Open questions

  • Is the approach shown above the answer or inside it? The canvas shows both.
  • Relevant later: «Det jeg ikke fant» has no data. The step and its link «Utdyp hva som mangler» need the platform to say what it looked for and did not find, and where it looked. No strategy sends this today, so only the example data shows the step. Built when the platform can send it.
