Use it when

  • Documents: the reader should see which documents the answer on screen came from, with a link to each where there is one.
  • OwnDocuments: the reader can add documents of their own, or will be able to.
  • DocumentsInScope: the filter's panel should say how many documents the next question reads from.

Don't use it when

  • To show what each document says. That is Sources, with the excerpts.
  • To mix the reader's uploads into the collection's list. They have their own section.

Variants

  • Before an answer: «Dokumentene som er relevante for søket ditt vises her.»
  • Five or fewer: all of them. More: five, «Viser 5 av 7 dokumenter.» and «Vis flere dokumenter».
  • Upload on: «Dine dokumenter» with the tag «Ny», a drop zone and the reader's files.
  • Upload off: the zone switched off, the tag «Kommer snart», and what is coming.
  • In scope, open or folded: the count, and the documents with a tick each where the host has them.

Props

  • Documents: documents, the documents behind the answer on screen, where a new array starts the list over; corpus, the collection, which names the list; corpusLine, drawn under «Dokumenter», such as CorpusLine; visible, the rows before «Vis flere dokumenter», 5 by default; headingLevel, 3 by default; and className.
  • A document is id, title, url where it can be read, about, its type, organisation and year for the line under the title, and own for the reader's upload, which this list leaves out.
  • OwnDocuments: documents, the reader's files; onUpload, called with one file at a time, and without which the zone says «Kommer snart»; onRemove with a file's id; accept for the file input; types, the types taken as a reader writes them, «PDF» and «.docx»; maxBytes, the largest file; headingLevel, 4 by default; and className.
  • A file is id, name, type, size in bytes, status (uploading, ready or failed), progress from 0 to 100 while uploading, and error when it failed: too large, the wrong type, failed, or upload not available.
  • DocumentsInScope: count, the documents the next question reads from; total, the collection's size; corpus, which names it; documents, most relevant first, each with id, title, type, organisation, year, pages and included; onIncludedChange with an id and whether it is ticked; defaultOpen, open unless false; headingLevel, 3 by default; and className.

Where it goes

  • In the UI assembly, under the filter's fields when the layout's filter has documents on: Documents with the answer's documents, or DocumentsInScope with the count and the total in the filter's panel. genki lists no documents for a filter and cannot leave one out, so that box draws no list and no ticks there.
  • The UI assembly draws no OwnDocuments yet.

Branding

A brand is a Designsystemet theme. The three parts sit in @layer genai.components, after Designsystemet's layers, follow data-color, data-color-scheme and data-size, and read every token through their own variable, with the token as the fallback. Set one on any ancestor to change that detail only. The muted text is pinned to neutral on purpose, so it stays grey whatever family the links beside it follow; why an upload failed is pinned to danger; and «Dokumentene som blir med» keeps the dev boards' neutral box, with its fold and the type tags in accent. In the markup, «Vis flere dokumenter» and «Fjern» are pinned to neutral, as kunnskapsassistenten draws them.

What is built

  • Documents: «Dokumenter», the corpus line, and the list named by a heading one level down, «Fra Kudos», or «Fra standardsamlingen» when the collection is not known. A title with a url is a link that opens in a new tab and says so to a screen reader; without one it is text, and the line under it says «uten lenke». The reader's uploads are left out of the list and its count.
  • «Vis flere dokumenter» shows the rest, goes, and moves focus to the list, which is focusable but not in the tab order. The next answer's documents start over at five.
  • OwnDocuments: «Dine dokumenter» with a tag, and Designsystemet's file upload, «Last opp egne dokumenter», with the types and size the host gives, such as «Kun PDF og .docx for øyeblikket, maks 20 MB». Files go up one at a time; a file that fails does not stop the next, and the same file can be picked again.
  • Each file shows its name, type and size, «Laster opp … 40 %» while it goes up, and why it failed. A size is written as a file manager does, in decimal units; the limit is in the unit the host checks it in.
  • A live region already in the page says when a file starts, is ready or failed, never the percentage, and nothing about files there when it was drawn. «Fjern» has the file's name in its name; after a remove, focus goes to the next file, else the one before, else the file picker.
  • Without onUpload, the zone stays, switched off: its input is disabled, so it takes no tab stop, and it says what is coming. A file dropped on the section gets «Opplasting er ikke tilgjengelig i denne tjenesten ennå.» instead of opening in the browser.
  • DocumentsInScope: «Dokumentene som blir med», a heading whose whole row folds the box with «Skjul» and «Vis». The count reads «Assistenten leser fra 8 781 av 45 778 dokumenter i Kudos», or without a total «… 8 781 dokumenter i Kudos». With neither a count nor documents, nothing is drawn.
  • With the host's documents: «Mest relevante først», a search by title or organisation, and a tick per document with its type as a tag, its organisation, year and pages. Without onIncludedChange the ticks are switched off, so none seems to work that does not.
  • The words are the block's own catalogue, in bokmål and English.

What we have learned

  • A title that is not a link reads as broken unless the row says why, so the line under it says «uten lenke».
  • A switched-off drop zone must still take the drop, or the browser opens the file and the reader loses the page.
  • A screen reader hears that a file started, is ready or failed, and no percentage: three announcements per file (WCAG 4.1.3).

Open questions

  • Where do own documents live? genki takes documents with each question, in text formats only, while kunnskapsassistenten's upload is for PDF and .docx kept per reader. Per reader, per thread or per project?
