Branding

How a service gives every block its own look the way Designsystemet does: a theme changes all of them at once, and a variable changes one detail of one block. The blocks carry no colours of their own.

Issues
kunnskapsassistenten#229, #170
Builds on
Designsystemet's themes, data attributes and cascade layers

Three levers, from broad to narrow

  1. A theme changes every block, and the rest of the app, at once.
  2. Designsystemet's attributes change a part of the page: data-color, data-color-scheme and data-size.
  3. A block's own variable, --genai-<block>-<element>-<property>, changes one detail of one block.

1. Load a theme

Designsystemet's CSS first, then the theme, then the blocks. Here with Altinn's theme, one of the four in @digdir/designsystemet-theme (altinn, digdir, portal and uutilsynet). genki's portal, console and workspace load digdir.css from the same package. 

@import '@digdir/designsystemet-css';
@import '@digdir/designsystemet-theme/altinn.css';
@import '@genai/ui-blocks/styles.css';

A service with colours of its own makes its theme with Designsystemet's theme builder, or its command line. Each colour it is given becomes a whole scale, for light and dark mode. Kunnskapsassistenten's theme is made from this file, designsystemet.config.json: 

{
  "$schema": "node_modules/@digdir/designsystemet/dist/config.schema.json",
  "outDir": "./design-tokens",
  "clean": true,
  "themes": {
    "digdir": {
      "colors": {
        "accent": "#0062BA",
        "brand1": "#F45F63",
        "brand2": "#E5AA20",
        "brand3": "#1E98F5",
        "neutral": "#1E2B3C"
      },
      "borderRadius": 4,
      "typography": {
        "fontFamily": "Inter"
      }
    }
  }
}
npx @digdir/designsystemet tokens create --config designsystemet.config.json
npx @digdir/designsystemet tokens build -t ./design-tokens -o ./design-tokens-build

The build writes one stylesheet named after the theme, here design-tokens-build/digdir.css, which takes the place of the theme in the imports above.

2. Set the attributes

<html lang="nb" data-color-scheme="auto">
  <body data-size="md" data-color="accent">
  • data-color-scheme: light, dark or auto, which follows the operating system. The Settings block lets the reader choose; the app stores the choice and sets it here.
  • data-color: the colour family for everything inside, such as accent, neutral or brand1. A block's color prop sets it on that block only, and only when given, so with no prop the block follows the app.
  • data-size: sm, md or lg.

3. Change one detail of one block

Every value a block uses is read through a variable of its own, with a Designsystemet token as the fallback. Set the variable on any ancestor, and only that detail changes. Each block's page lists its variables, their defaults and what they style. 

/* Outside every layer, so it wins over the blocks' defaults. */
.service-settings {
  --genai-settings-gap: var(--ds-size-6);
  --genai-settings-section-gap: var(--ds-size-2);
}
  • Give a token, not a literal, so the value still follows the theme, dark mode and data-size.
  • Set the variables, not the blocks' uib- classes. The classes are inside the block and may change; the variables are what a block promises.
  • Designsystemet's components inside a block keep their own --dsc-* variables. A block adds a --genai- variable only for a value it gives them itself.

Why an app's own CSS wins

The blocks' styles sit in @layer genai.components, declared after Designsystemet's ds.theme, ds.base and ds.components. CSS an app writes outside any layer wins over all of them, with no !important and no contest of selectors.

What every block keeps to

  • No colour of its own: only Designsystemet's tokens.
  • No bare token or literal: each is the fallback of a --genai- variable.
  • Its font is set on its own root, through --genai-<block>-font-family, so a font can be given to one block.
  • A colour pinned to one family is pinned on purpose, named in the stylesheet, and listed on the block's page.
  • A test fails a block's stylesheet that breaks one of these.
  • Approach, the first block, does not set its own font yet.

Open questions

  • Where a service owner picks the brand colour: the app builder's brand step, which makes the theme (kunnskapsassistenten#170).
  • The --genai- prefix follows the package's scope, and is to be agreed with genki's maintainers before the first release. After it, renaming a variable breaks the apps that set it.
