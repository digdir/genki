Use it when

  • Users come back to earlier conversations.

Variants

  • Threads and filter in one panel (HI-A4): «Filtrer dokumenter» above «Ny tråd», when the host passes onShowFilters.
  • Thread menu: rename and delete, each only when the host can. Moving a thread waits for Projects.

What it does

  • Groups the threads by period: «I dag», «Siste 7 dager», «Siste 30 dager», the months of this year, then the years, newest first, in Oslo time. Each row is dated as briefly as its heading allows.
  • One line per title; a cut title shows the whole row in a box on hover or focus (WCAG 1.4.13). The link's name is the title alone.
  • «Søk i tråder» filters as the person types and counts what is left. Over an empty list there is no search, and «Ny tråd» reads «Start din første tråd».
  • A rename happens in the row; a delete asks first. Both show at once, focus lands on the row's menu or the next row, and a screen reader is told what happened.

Props

  • threads: id, title (the contract's topic), updatedAt (ISO text, epoch milliseconds or a date) and an optional dataset. Undefined while they load.
  • threadHref and onOpenThread: each row is a link, and a plain click goes to the host's router. A click for a new tab is the browser's.
  • onRename and onDelete: events the host handles. Return a promise, and the block shows the change at once and puts it back, with a message, if it rejects. It keeps the change until the host's list moves past it, so a read that was already out cannot undo it. A thread the host finds already gone: resolve the rename with 'gone', and its row goes with a message; resolve the delete, which then counts as done.
  • onShowFilters and focusShowFilters: «Filtrer dokumenter» over the list, for a filter that shares the panel, with focus on it when the person just came from the filter. headingLevel, 2 by default, for the list's hidden heading, with the groups one below. color: Designsystemet's data-color, set only when given.
  • failed and onRetry, currentId, newThreadHref and onNewThread, and a foot slot for who is signed in, named as the shell's panels name theirs (footer still works until hosts have moved).
  • SignedIn, for the foot: the reader's name, with the email on hover, and «Logg ut», a plain link to signOutHref. onSignOut comes before the browser leaves, a middle click included, so the host can forget what this browser kept for the reader: the filter, the collection, the experiments. It stands after the last row and scrolls with the list, so it never covers a row the keyboard has reached.

Deleting the thread on screen is the host's to follow up: it opens a new thread in onDelete.

Branding

A brand is a Designsystemet theme. The block sits in @layer genai.components, after Designsystemet's layers, follows data-color, data-color-scheme and data-size, and reads every token through its own variable, with the token as the fallback. Set one on any ancestor to change that detail only. Four are pinned to neutral on purpose, as the reference draws them: the group headings, the time and dataset under a title, «Ingen treff», and the line above who is signed in.

What we have learned

  • Built from kunnskapsassistenten's thread list, with its look, wording and tests. The platform's Conversation has no time of the last change, so a host passes created as updatedAt, as kunnskapsassistenten does.
  • Times read as kunnskapsassistenten writes them, «14:32» and «kl. 09:05», not in the platform's «14.32». Its views are the reference for these blocks (decided 2026-11-03).
  • The thread is above the sources. A thread has its own document selection, and each question remembers the selection it was asked with.
  • Don't put «Kilder» and «Tråder» side by side, for example in a tab selector. The filter belongs to one thread and shows the documents for it.
  • No counter for the number of threads.
  • Collapsed, the primary sidebar shows only the show button, «Ny tråd» and «Tråder».

Open questions

  • How do we show that a thread owns its document selection, if «Kilder» and «Tråder» aren't side by side?
  • Can an assistant work without threads? Every example in the canvas has them.
  • Should the list sort by the last answer rather than the start? That needs a time of the last change on Conversation.
