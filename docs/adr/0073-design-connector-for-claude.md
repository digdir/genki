# 0073 Designers send designs from Claude through a connector

Status: proposed, 2026-11-26 (built, behind `blockStudio` and `GENAI_PUBLIC_API_URL`)

Left: Client ID Metadata Documents, a structured and verified «Fra Claude» marker, importing a design that needs code (ADR 0067), and connecting from Claude Design, which offers no custom connectors.

## Context

Designers work in Claude (claude.ai, Claude Desktop or Claude Code). Block Studio's «Åpne i Claude» only opened claude.ai with a prompt in the URL, and the design came back by copying HTML into «Importer fra Claude». Claude reaches outside services through custom connectors: remote MCP servers over Streamable HTTP that it authorizes with OAuth 2.1, PKCE and the metadata of RFC 9728 and RFC 8414. A connector is added once per Claude organisation by an owner, or by each person on Free, Pro and Max, and in Claude Code with `claude mcp add --transport http`. Claude stays outside genki: genki only offers the connector.

## Decision

- **A design connector on the API.** When `GENAI_PUBLIC_API_URL` is set (an https origin; http on localhost only in dev mode) and the portal's origin is known, the API serves `/mcp/design`, `/oauth/design/*` and the `/.well-known/oauth-*` metadata documents from `apps/api/src/design-connector`, on the API's own host only. They are dispatched before the BFF and the app, so they answer OAuth and JSON-RPC errors in their own shape. The MCP URL is the OAuth resource, and the metadata name it exactly.
- **Three tools.** `list_design_elements`, `get_design_element` and `import_design`. A tool call runs the API's own routes in-process as the grant's principal (`connectorCaller()` in `composition.ts`, honoured only on a request that carries the call's random nonce), so rights, lockdown, flags, the change log and the audit log apply as for the portal. `import_design` runs the same import as the paste path (`POST /tenants/{tenant}/blocks/import`, no code) and saves the result with `POST /definitions` as a new edition shared with the organisation, Block Studio's «utkast»: no service uses it until a person pins it. It never pins, and an edition from Claude is never shared wider than the organisation, even when the element's earlier editions were. A new edition from Claude is taken only by a declarative element of the organisation's own. Text from genki goes back inside untrusted-data tags, as in ADR 0046.
- **Clients.** Dynamic client registration (RFC 7591) keeps nothing: the client id is the registration sealed by the BFF session store. Redirect URIs are only `https://claude.ai/api/mcp/auth_callback`, `https://claude.com/api/mcp/auth_callback` and `http://localhost`, `127.0.0.1` or `[::1]` on any port with the path `/callback` and no query or fragment. An authorize request with an unknown client or redirect gets a page, never a redirect. PKCE S256 is required, the scope is `design`, and a `resource`, when given, must be this server.
- **Consent in Block Studio, finished in the browser that started it.** Authorize sets an HttpOnly, Secure, SameSite=Lax cookie on the API's host (`__Host-genki-design-<request>`, five minutes) holding a random value whose digest is kept on the pending request, and sends the person to the portal at `#/design/connect/<request>`, where genki's own login applies. The person sees the client's name (untrusted text), the organisation, when the connection was started and where the code goes, with a warning to approve only a connection they just started. Allowing (`POST /tenants/{tenant}/design-connector/requests/{request}` with a change reason, through the BFF with its Origin and JSON checks) only records the approval; the browser then goes to `GET /oauth/design/finish/{request}` on the API, which issues the code and redirects to Claude only when the cookie matches. A request finished without it is ended with a page and no code. Denying sends `access_denied` back to Claude. A request lasts five minutes and is approved and finished once. Only a person with `manage-services` in that organisation and `blockStudio` on may approve, and the portal follows only the finish address of that request, Claude or loopback.
- **The grant.** It is a snapshot of the person narrowed to the one organisation, and an operator is held to the rights of an employee there. Requests last five minutes, codes 60 seconds, access tokens 15 minutes and a grant 8 hours. Refresh tokens rotate, and an old one used again ends the grant, unless it comes again within 30 seconds of its rotation (a client retry), which is refused without ending it. A refresh token presented by another client is refused and ends nothing. Tokens are `<grant>.<secret>`, compared by digest, and taken only from the `Authorization` header. Rows live in the BFF session store under the platform tenant. «Koble fra Claude» (`DELETE /tenants/{tenant}/design-connector/grants`, reason-free like other personal writes so it works in lockdown) ends the person's grants and unspent codes in every organisation. RFC 7009 revocation ends a grant only for the client it was issued to and only with a live access or refresh token. On every refresh the connector calls `GET /tenants/{tenant}/design-connector/grant-check` in-process as the grant's person, the same tenant and `manage-services` check as consent behind `blockStudio`, and ends the grant when it fails. The tools check `blockStudio` before every call.
- **Audit.** Approving is `platform.design-connector.connect` (`manage-services`), «Koble fra Claude» is `platform.design-connector.disconnect` (`use-services`, audited in the organisation it was called in), both with the person as actor. Every import is a version with the reason `Importert fra Claude: <name>`, and the catalogue shows it as «Fra Claude» (`latest.fromClaude`).
- **Limits.** 20 registrations and 30 authorizations a minute per address, 60 token requests a minute per client, 120 MCP calls and 10 imports a minute per grant, 30 unknown bearer tokens a minute per address before that address is refused without a lookup, 1 MiB per MCP body, 512 KiB of HTML and 16 KiB per form.
- **Block Studio.** «Koble til Claude» replaces «Åpne i Claude» and opens a guide with the connector's address and a copy button, the steps in Claude, the Claude Code command and «Koble fra Claude». The paste path in «Importer fra Claude» stays as the fallback.

## Why

- A connector is the one way Claude can deliver a design to genki by itself. The URL prompt carried nothing back.
- Calling the API's routes in-process, instead of a second implementation, keeps one place for every rule. A path that skips a check is the mistake this repository fixes most.
- Turned down:
  - **Client ID Metadata Documents.** The server would fetch a URL chosen by the client, a request forgery surface, for nothing Claude needs: Claude registers dynamically.
  - **A static client per organisation.** Every organisation would have to copy a secret into Claude, and Claude Code users could not connect.
  - **Only the local admin MCP server of ADR 0046.** It needs Node and a checkout, which designers in claude.ai do not have. It stays for coding agents.
  - **Claude Design export.** It sends only to a fixed list of partners, and its HTML export already works through the paste path.

## Consequences

- ADR 0046 turned down an MCP endpoint on the API because it adds a surface that needs its own review. This record is that review for one narrow surface: three tools, new editions only, one organisation.
- An operator sets `GENAI_PUBLIC_API_URL`. Infra sets it from the API hostname when platform login is on. A Claude Team or Enterprise owner adds the connector URL under the organisation's connector settings before members can connect. Anthropic calls from 160.79.104.0/21.
- Residual risks: a grant is a snapshot of the person at approval. The refresh check sees what genki itself knows (the tenant, `blockStudio`, the rights it computes from the snapshot), not a later change in Altinn, an Entra group, a back-channel logout or a refused Entra login; those end the grant only through «Koble fra Claude», revocation or expiry within eight hours. The browser cookie stops someone from approving a connection started in another browser; a person tricked into starting and approving a connection in their own browser is still covered only by the warning and by Claude binding `state` to its own session. Registrations from claude.ai come from few Anthropic addresses, so they share the per-address limit. The «Fra Claude» marker is declared by the reason, not verified, as in ADR 0046, and the paste path's own reason does not carry it; the audit entry of the import is the verified record. Without a database the rate limits count per process.
- Tests: `apps/api/src/design-connector/design-connector.test.ts` ("lets Claude send a design as a draft of the organisation and links to it in Block Studio", "refuses a design that needs code and saves nothing", "keeps a grant to the organisation it was approved in", "never keeps operator rights in a grant", "revokes a grant only for the client it was issued to and only with a live token", "issues no code when the approval is finished in a browser that did not start the connection", "cannot approve a connection started more than five minutes ago", "ends the grant on refresh when the person it acts for lacks manage-services", "refuses tokens from an address after too many unknown ones, before looking them up", "never takes an access token from the URL", "never redirects to a URI the client did not register", "rotates the refresh token, and ends the grant when an old one is used again", "limits the imports one grant may send in a minute"), `apps/portal/src/screens/design/connect-request.test.tsx` ("refuses to send the browser anywhere but Claude, this machine or the API that finishes it") and `catalogue.test.tsx`.
