# 0054 An assembly draws an assistant from a layout

Status: proposed, 2026-11-11 (partly built: the layout, its catalogue, rules and templates, and `@genai/ui-assembly`; a block in both its zones, 2026-11-13; the host's headers, 2026-11-13; the look a layout setting, and a template's options, 2026-11-13; the profile as data in the layout, 2026-11-14; the portal's try view draws it, 2026-11-14; a question the host refuses taken back, 2026-11-14)

Left: where a layout is stored, such as a frontend part of the service definition; texts in more than one language; and suggestions from the service's example questions, which `/v1/models` does not carry. Each needs its own change.

## Context

ADR 0053 keeps the UI blocks free of fetching: data in, events out. It left two things for their own decision: a layout format, which says which blocks a service has and where they sit, and a package that fetches, which turns what genki sends into the blocks' props.

## Decision

- **A layout is data.** `AssistantLayout` in `packages/ui-blocks/src/builder/layout.ts`, version 1, places blocks in the shell's three zones, `primary`, `main` and `secondary`, each with only the settings that differ from the block's default.
- **One catalogue says what a layout may hold.** `blockCatalogue` in `builder/catalogue.ts` lists each block, its options, the zones it may sit in and what it needs from a partner. `isAssistantLayout` and `layoutProblems` in `layout.ts` check a layout against it.
- **A block stands in one zone, or in both its zones where the catalogue says `both`.** The layout then lists it once in each, and the assembly draws it in each its own way. It has one set of settings: the builder writes them alike in each zone, and `settingsOf` reads the first zone's. Only Fremgangsmåte is marked `both`: the card over each answer in `main`, the detailed tool in `secondary`, and beside the tool the card is compact. `layoutProblems` reports `placed-twice` for any other block placed more than once, and for any block placed twice in one zone. The builder offers the places with `placesOf`: each zone, then `both`.
- **A template is a named layout,** in `builder/templates.ts`, such as `knowledge-assistant`. A template may also set a look and options that differ from the blocks' defaults (`templateSetups`), which `fromTemplate` writes into the layout: `knowledge-assistant-next` sets the look `next`, feedback on and follow-ups off.
- **The look is a setting of the layout.** `AssistantLayout.look` is optional, `current` or `next`, and the layout stays version 1. `lookOf` reads it; a layout without it is drawn in its template's look (`templateLook`: `next` for `knowledge-assistant-next`, `current` for every other), as every layout was drawn before the field. Changing blocks or options keeps the look, and `changeTemplate` keeps it too, unless the new template sets its own. `isAssistantLayout` refuses a look it does not know. A new look sits behind this setting, or behind props and `--genai-*` variables whose defaults keep today's look, so an existing layout never changes by itself, apart from the one change to `knowledge-assistant-next` under Consequences.
- **An option may belong to some looks only.** A catalogue option with `looks` is in force only in those looks (`optionInForce`). Chat's `followUps` is `current` only, since the next look draws no follow-ups.
- **A layout may carry its profile as data.** `AssistantLayout.profile` is optional, `ProfileData` in `builder/profile.ts`, and the layout stays version 1. It is the part of the assembly's `AssistantProfile` that JSON can hold: `assistantName`, `suggestions`, `followUps`, `experiments`, `settingsNote`, and per collection, by its key, `label`, `description`, `fields` (each `id`, `label`, `heading`, `kind` and `years`), `typeField`, `typePlurals`, `documentLinks` and `about`. What only code can say stays the host's: the reader (`signedInAs`, `organisation`), `menu`, `signOut`, `family` and `documentUrl`. Whether a field's values are integers is the dataset's `value-type`, which `loadFields` reads when a profile does not say. `withProfile` sets or clears it, and `changeTemplate` keeps it.
- **The profile is checked like the rest of the layout.** `isAssistantLayout` refuses a profile of the wrong shape, a field `kind` or a link's kind of number it does not know, and years that are not whole numbers; a key it does not know is passed over, as the layout's are. `layoutProblems` reports, each with its path: `profile-too-large`, over 32 KiB as JSON in UTF-8; `text-too-long` and `too-many`, past the limits in `profileLimits`; `link-not-https`, a link or link template that is not an https address whose host comes before `{id}` and names no user; and `unknown-kind`.
- **The host's profile wins where it says something.** `profileOf(layout, host)` in `@genai/ui-assembly` takes each value the host sets, and the layout's for the rest. A list the host sets wins whole, an empty one too; `undefined` sets nothing. Each collection is filled value by value, so a host's `documentUrl` goes first and the layout's `documentLinks` link what it does not. Without a profile in the layout it is the host's own object. `useAssistant` draws with it, and a host that makes its api with `createGenkiApi` passes it the same, so the fields, the collections' names and a stored answer's links are in its words.
- **`@genai/ui-assembly` is the one UI package that calls genki.** It sits beside `@genai/ui-blocks` among the consumers and depends on `@genai/client`. It holds the state the blocks share (`useAssistant`), places each block of a layout in its zone (`<Assistant>`), and turns genki's answers and stream into the blocks' props. The blocks stay free of fetching.
- **One interface to genki.** Every call goes through `AssistantApi`. `createGenkiApi` implements it with reads (models, threads, collections, fields, facets), a new thread and a question; tests use a fake.
- **No key in the page.** `createGenkiApi` takes a `baseUrl` and holds no credentials of its own. A host reaches genki through its own proxy or session, which adds the key or the person's token, or gives `createGenkiApi` a `headers` callback, such as one that returns the person's Bearer token. The assembly calls it before every request, the question's stream included, and a header the assembly sets itself, such as `Accept`, stays its own. Without it, nothing is added. A `401` fails the call with that status, which the assembly calls access, and stops a question at its new thread.
- **A host may refuse a question before it is asked.** An `ask` that throws `NotAsked` before it yields anything asked nothing: the assembly takes the question out of its thread, with no failed answer, puts a question typed in the field back there while its thread is on screen and the field is empty, and lets the answers in other threads go on. The host says why, as the portal's try view does above the preview. Thrown after it has yielded something, it is a failed answer.
- **Writes other than a question are the host's.** Feedback goes to the host's `onFeedback`, with the answer's `runId` (genki's task id) when genki gave one; without `onFeedback`, no feedback is offered.

## Why

- A service owner's preview and an app such as Kunnskapsassistenten should draw the same assistant from the same layout, without breaking 0053's rule for the blocks.
- A layout as data can be edited by the builder, checked by a host and stored later. The catalogue keeps one table: the builder proposed in #210 had its own rules.
- Turned down: fetching inside the blocks, which breaks 0053; and each host writing its own wiring, which would drift as the builder's sketches and the workspace's chat did.
- A host such as the workspace calls genki with the person's token and has no proxy, so it hands the assembly headers. Turned down: a `fetch` for the host to wrap, since the assembly's own requests carry their headers in two shapes, a plain object and `@genai/client`'s `Headers`, and each host would have to merge both without losing `Accept` on the stream.
- A block in both zones is placement, so it is said where placement is said, in the zones, and a layout that places a block once is unchanged. Turned down: an option on the block, `place: card | tool | both`, which would say the same thing as the zone it stands in and could contradict it.
- The look is the layout's because a template is where a layout starts, not what it is: tied to the template's id, the look was lost as soon as the builder chose another template. Turned down: a layout version 2, since a layout without the field means what it meant; and keeping the look in the template's id, which a builder cannot change without changing the blocks.
- The profile goes with the layout because a service made in the builder has no host code: without its words it is drawn with genki's names, and the layout is what the builder edits and a host stores. The host's code still wins, so a host that passes a full profile draws what it drew. Turned down: functions or regular expressions in the data, since a link is chosen by a fixed kind of number, so nothing a profile holds is run or turned into a pattern; and http links in stored data, which take the reader to a document in the clear, with its number in the address.

## Consequences

- The atlas has a module `ui-assembly` (`docs/architecture/modules/ui-assembly.yaml`), and `docs/components/ui-assembly.html` describes it.
- The portal's try view, in the service page's «Grensesnitt» tab, is its first host. Kunnskapsassistenten's next client and the workspace can follow.
- The layout's version 1, `AssistantApi` and the assembly's props are public once the package is published: changing them then breaks a host.
- The assembly's stylesheet follows the blocks' rules, and its lint refuses literal colours.
- In the template `knowledge-assistant-next`, Fremgangsmåte stands in both zones. Its look drew the tool for Fremgangsmåte in `main` before this was a choice, so a layout from that template stored earlier with Fremgangsmåte in `main` alone now draws the card alone.
- A layout made from `knowledge-assistant-next` now holds `look: 'next'` and Chat's `feedback: true` and `followUps: false`. Feedback is still offered only when the host gives `onFeedback`. A layout stored earlier from that template still draws the next look, and its follow-ups stay off, as they were.
- A builder that offers the look as a choice names it with `lookKey`, in the catalogue's words.
- The profile's shape is part of the layout's version 1 once a layout with one is stored: changes to it are additive, and a new field kind or kind of number is refused by a host that does not know it, as a new look is.
- The limits are `layoutProblems`', so a builder or a store that checks a layout keeps to them; a host that draws a stored layout without checking it draws a long text as it is. The https rule holds either way: `profileOf` drops a layout's link or link template that `isHttpsLink` refuses, while a host's own links stay as the host gives them.
- A field a profile chooses without saying whether its values are integers is now sent as the dataset declares it, where it was sent as text.
