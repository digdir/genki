# 0017 Parity scope and intentional divergences

Status: accepted, 2026-10-12 (built). Proposed 2026-10-06. Extended 2026-10-09 with every divergence the parity audit found.

## Decision

Parity means: today's clients (KA, Open WebUI, MCP clients) see the same behaviour. The new platform deliberately does not reproduce the behaviours below. Each row is in one of these states:

- **Different**: it works, but a client or operator can notice the difference. The row says why it is acceptable.
- **Dropped**: deliberately not offered. The row says why.
- **Missing**: not offered yet and not agreed as a drop. Each Missing row needs a decision before KA switches.

Security behaviour is never copied from headless-rag. It follows ADR 0002 and ADR 0008, whatever the old system did.

Everything else headless-rag does that a client can observe is reproduced. That includes MCP headers, error codes, cache hints, the three result channels, SSE timing, `/v1` model listing, and the conversation API. Services are reached by their own names (`<service>__<variant>`), not headless-rag's agent names, which were removed on 2026-10-09. `_agent_id`, `_mode` and `agent` are kept for compatibility; `_service`, `_variant` and `service` are the platform names (ADR 0031). A behaviour that is not in this ADR is a bug, not a divergence.

## Other divergences

These rows have no parity scenario, because they concern routes no known client calls, operator tooling, or behaviour inside a run.

## Consequences

- Each Different or Missing row that KA or another client could notice is agreed with that client before the switch.
- Security fixes are never blocked by parity.
- A new row goes in this ADR in the same change that introduces the divergence.
- [ADR 0042](0042-the-knowledge-database.md), proposed, changes three rows when it is built: the failure-budget row (runs update documents in place), the Marker row (the queue's retries replace the ladder, ADR 0041) and the executions row (a second run of a pipeline waits instead of being refused).

## Closed in this round

The parity audit of 2026-10-09 listed these as gaps. Each is now covered or has a row above: `_meta.insufficient` and `_meta.execution_metadata` (`packages/strategy-agent-loop/src/execution.ts`), MCP conversation history and persistence (`packages/conversations/src/turns.ts`), `/api/datasets` status, the ingestion gaps, rerank in the agent's search (`packages/retrieval/src/factories.ts`), the EPiServer loader and Kudos profiles (`packages/ingest/src/episerver.ts`, `kudos.ts`), security headers, gzip, `/up`, the rate limit across replicas, conversation-create status codes, key grants and the KA capability probe.

Open Web UI as a `/v1` client end to end and deployment are outside parity: both depend on a deployed platform.

## Parity harness names

The parity harness maps each capability to a headless-rag name and a platform name in `apps/parity/scope.json`; `apps/parity/src/names.test.ts` fails if a platform-side name is not served by the seeded definitions.

The separate service `kunnskapsassistenten-retrieve-only` is a headless-rag compatibility service: it stands in for `builtin.retrieve-only-agent` so existing clients keep a name to call. New clients use the `retrieve-only` variant of Kunnskapsassistenten, shown as one service with a variant picker.
