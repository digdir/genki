# 0047 One governed path for model operations

Status: proposed, 2026-11-03 (gate as a wrapper and payload guard in the gate built, 2026-11-03; operations on the catalogue and `decide` built, 2026-11-03; closed payload shapes, the gate as the only governed path and calls outside a run built, 2026-11-03; operation descriptors, the executor, `operation@1` and the raw tier built, 2026-11-03; the described tier, maturity per kind and processor records built, 2026-11-03; the outside-run log's retention built, 2026-11-03; one-operator promotion, 2026-11-03)

## Context

Model providers add a new kind of API every month or two: decisions, image, speech, realtime, batch, provider-side files and agents. Genki reaches models through three separate stacks (`port-model`, `port-embedding`, `port-rerank`), each with its own router, and the governance in them already differs: only the model router checks lockdown admission (ADR 0033), rerank meters nothing, the embedding router has no egress guard and no tenant sharing, and search embeddings outside a run are metered into a no-op. PII masking and hooks wrap only the port named `model` (`packages/guardrails/src/strategy.ts`, `packages/hooks/src/strategy.ts`), so a new port would skip them without anyone noticing. Issue #248 (the Azure OpenAI Decisions API) is the first new kind that needs a decision.

## Decision

### One gate

Every model call passes through one gate in the kernel, `packages/kernel/src/gate.ts`, whatever its kind. The gate does, in this order and nothing else: admission, enabled, tenant sharing, every residency ceiling (router, request, service), the payload guard on the request, the call through the egress-guarded fetch, usage into the meter, provenance, the audit event `kernel.gate.call` (port, operation, model, endpoint, status, byte counts, never the body), then the guard on the result. The three routers call the gate; their own copies of these checks are removed. Each port declares its admission explicitly instead of having none by accident: embeddings are `open`, as ADR 0033 intends, and rerank is admitted like chat.

### The payload guard moves into the gate

The PII vault and the before- and after-model hooks are handed to the gate as a `guard` on every `use`, not wrapped around one port by name. A call whose payload has image, audio or file content is refused unless the guard allows unmaskable input (below).

### Closed payload shapes

Every operation declares a closed payload shape (`packages/kernel/src/payload.ts`): where text, images, audio, files, ids and usage sit in the request, the response and the stream events. There is no `any` field. One walker uses the shape to mask, restore, find media and validate:

- an unknown field in a request is refused before anything leaves Genki;
- an unknown field in a response is dropped and counted in the audit event;
- an unknown stream event ends the stream;
- a URL or a provider-side object id in a request is refused.

### Operations on the catalogue

A catalogue model carries `operations` (default `['chat']`) next to `capabilities`. An operator classifies the operations a deployment serves, as ADR 0044 prefers evidence to guessing from names. An adapter implements the operations it supports; a call to one it does not implement fails as `unsupported` (ADR 0023). The first new operation is `decide` (#248), exposed as the kernel port `decision` over the same routes, so grants, `use:decision` policy and the audit event come from the kernel.

### Descriptors and three tiers

A new kind can arrive without hand-written types through an operation descriptor: a versioned file with the endpoint path, the payload shape, the usage mapping and the stream events, keyed on the API version and any beta headers. Descriptors are reviewed like code and proven against recorded fixtures in the contract suite `operation@1`; they are never edited in the console. One executor turns a descriptor into a gated call and rewrites the model field to the catalogue deployment, so a caller cannot pick another deployment.

| Tier                      | Who may call                                                                   | Guard                                                                 |
| ------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Raw: descriptor in review | Operators, as a kernel task, synthetic data, test only                         | All PII categories masked always, media refused, admitted logins only |
| Described                 | Services, through a `call-operation` step block, once the kind is `production` | The service's own guardrails                                          |
| Typed                     | Services and strategies through Genki's own types                              | The service's own guardrails                                          |

A raw use that a service depends on becomes described or typed before the service may publish it.

### What a call must meet before it carries real data

1. It runs inside a published service version, or it is an operator call marked synthetic. Anything else is refused.
2. The endpoint's residency is within the service's at publish and at call, and the endpoint has a processor record: its data processing agreement, sub-processors with locations, and provider-side retention. An endpoint without one cannot serve a service with real data.
3. Every text field is masked and guarded. Image, audio and file input is refused unless the service's confirmed risk assessment records `acceptsUnmaskedInput` with reasons.
4. Every call is audited as who, what, where and how much; the payload is kept only in the encrypted store under the service's retention.
5. Each operation kind has a maturity, `test` or `production`. The environment declares its tier, and the gate refuses an operation whose maturity does not admit it, at publish and at call. One operator moves a kind to `production` or back to `test`, audited with who, when and the change reason.

### Decisions about people

A service whose decisions concern a natural person declares `decidesAboutPeople`. That requires the risk class `high`, a human step before a result is final, and the model input kept for review. A refusal or a low-confidence answer goes to a person, never to "no". Without the declaration, a decision may only concern content.

### Kept out

Realtime and live sessions, ephemeral provider keys in the browser, batch, provider-side files, vector stores and conversations, stored or background responses, hosted agents and tools, voice cloning and URLs the provider fetches do not go through descriptors. Each needs its own ADR, because each holds a session or keeps data at the provider, which conflicts with ADR 0044 and ADR 0045.

## Why

The three routers already disagree on governance, and each new kind built the same way would add a fourth copy that fails open where it is missed. Gateways that moved fast on decisions (LiteLLM, GoModel, LLM Gateway) were fast because auth, cost and logging sat in one place; what they added per kind was the shape. A closed shape, unlike a list of paths to mask, proves that the rest of a request carries no user content, so the raw lane can mask and meter instead of passing bodies through unread.

One operator, not two, moves a kind to production. The gate still refuses a real-data call without a processor record and keeps the raw tier to test with synthetic data, every change is audited with a reason and one operator can reverse it, and in a small team a second confirmer becomes a formality.

Turned down:

- A port per family with its own router and catalogue: it duplicates the deployment and the governance, and drifts.
- Opaque pass-through: it cannot mask, guard or reliably meter.
- An external gateway as the way in for new kinds: residency hides behind one URL, it adds a processor, and new kinds still wait for the gateway.
- JSONPath or the providers' OpenAPI specs as the descriptor language: paths locate text but do not prove the rest is harmless, and specs lag new features.
- Media scanning as a substitute for a recorded decision: it is not reliable enough to stand in for one.

## Consequences

- The gate ships as a wrapper around the existing routers first, behind two contract suites, `gate@1` and `operation@1`; the routers' own checks are removed only when the suites pass. CI enumerates every registered operation and descriptor, so a new one cannot ship unproven. The key test: "no operation sends a valid national id upstream when the service masks national ids", checked against the recorded request bodies.
- Moving the guard into the gate changes masking for every service run and must not mask twice.
- Rerank becomes metered, and embeddings get the egress guard and tenant sharing.
- The masker covers patterns for Norwegian ids, phone, email, account numbers and ICD-10 codes, not names or free-text health data. Masking reduces exposure; it does not make data anonymous.
- A new host, or a partner model sold under its own terms, may be a new sub-processor that agencies must be told about before their data reaches it. In production that notice, not the code, sets how fast a new kind can go live.
- Built (#277): `packages/kernel/src/gate.ts`, as a wrapper the model, embedding and rerank routers call, and the contract suite `gate@1` (`packages/kernel/src/gate-contract.ts`), run against the bare gate and against the three routers. The gate checks admission, enabled, tenant sharing and every residency ceiling, refuses image, audio and file content, masks and runs the guards, calls, meters, records provenance and writes `kernel.gate.call`; the egress guard stays in each endpoint's fetch. The PII vault and the model hooks are handed to it on every `use` (`UseOptions.guards`), and the service's residency with them. Embeddings and rerank have optional `tenants` in their catalogs. Rerank is metered as one request per call.
- Built (#248): catalogue models carry `operations` (default `['chat']`), set in the catalogue or by an operator (`PATCH /operator/models/{id}`), and a call to an operation a model does not list, or its adapter does not implement, fails as `unsupported`. `decide` is the kernel port `decision`, served by the model router (`ModelRouter.decisions()`) over the same catalogue, implemented in `openai-chat` against `/openai/v1/decisions`, with Genki's own types (`packages/port-model/src/decision.ts`). Its payload was the first closed shape; the adapter keeps only the documented response fields of the wire answer and counts the rest in `kernel.gate.call` as `dropped`. `decision` is a lane in `gate@1`, so the national id test covers it. `decidesAboutPeople` is checked at publish: risk class `high`, the `human-approval` guardrail as the human step, and no `pii-out-of-log`, since the run's input under the service's retention (at least 183 days for `high`) is what keeps the model input for review. The guardrail `purpose-check` is the first use; a refusal or an answer below its threshold interrupts the run for a person, or lets it through when the service says so, and is never a refusal. Decisions show in the run timeline and in the eval observation.
- Built (#290): `packages/kernel/src/payload.ts` holds the closed shapes of chat, decide, embed and rerank as the ports have them, and one walker that masks, restores, finds media and validates. The gate refuses a request outside its shape (`shape`) before and after the guards, refuses a URL or a provider object id in an identifier, drops an unknown answer field and counts it as `dropped`, and ends a stream on an unknown event. Text fields alone are masked; a URL inside text stays allowed. The replay state in `continuation` is not open: each adapter declares its shape (`ModelAdapter.continuation`), and the chat shape allows only those. The routers keep only routing: admission, enabled, sharing and residency are checked in the gate alone, so a refusal now comes when the call is made, not when the port is opened. `gate@1` checks the shapes and provenance, and runs against mutated gates that each leave one check out, which must fail. Adapters get their fetch from the gate (`Gate.egress`), which applies the endpoint's egress guard on every request. A call outside a run (no `audit` on its port context, such as ingestion and search) is audited and metered through `GateOptions.outside`; the runtime writes `kernel.gate.call` and `kernel.usage` to the log `outside-run:<tenant>:<day>`. The before- and after-model hooks run on `decide` with the input text and the answers, and operators see and set `operations` in the console and in the admin MCP's `list_models`.
- Built (#291): descriptors are YAML files in `packages/operations/descriptors/<provider>/<operation>@<version>.yaml`, data and never code, so a descriptor can only say what the one executor does. Each names its API version and the query and headers it is keyed on, the endpoint path relative to the catalogue endpoint, the typed input and output and the wire request and response in the vocabulary of `payload.ts`, a declarative mapping between them (`$input`, `$response` and `$deployment` paths, `$from`, `$default`, `$omitWhen`, `$each`, `$sort`, `$map`), the usage mapping and its stream events or `none`. Loading refuses a URL, a credential header, a path to a kept-out API and a wire field such as `store` or `previous_response_id`; a `typed` descriptor must declare the shapes Genki has for its operation. The executor (`describedCall`, `packages/operations/src/executor.ts`) runs through the gate with the descriptor's own shapes, builds the wire body from the masked input, sets the model to the catalogue deployment, refuses a body outside the wire shape, sends with the endpoint's credential through the gate's egress fetch, drops and counts unknown answer fields and meters the mapped usage; `kernel.gate.call` names the descriptor. A catalogue opts one operation in (`descriptors: { decide }` on a model, `descriptors: { embed }` on an embedder); the hand-written adapters stay the default. `openai/embed@1` and `openai/decide@1` send the same requests and give the same results as the hand-written adapters on their fixtures. `operation@1` (`packages/operations/src/contract.ts`) proves each descriptor against recorded fixtures in `packages/operations/fixtures`: the request built from the typed input, the result and usage mapped from the recorded answer, unknown fields dropped and counted, an input outside the shape refused before anything leaves, and only input text in a wire text field; `npm test` enumerates the descriptor folder, so a descriptor without fixtures fails. The descriptor executor is a lane in `gate@1`. The raw tier is the port `operation` (`ModelRouter.operations()`), opened only by the kernel task `platform.operation.try`, which an operator starts with `POST /operator/operations/{descriptor}/try`: refused unless `GENAI_ENV=test`, refused without `synthetic: true`, every PII category masked and never restored, media refused, in lockdown only for an admitted login, audited as an admin task and as its own run, and metered to the platform organisation. A service cannot open the `operation` port.
- Built (#292): the described tier is the step block `call-operation@1` in a service's step flow (`params: { descriptor, model? }`, the descriptor's typed input as the step input, `{ result }` out), served by the kernel port `described` (`ModelRouter.described()`), which a step-flow service is granted on each of its own models. A descriptor may have the status `described`, reviewed but without Genki's own types; one in `review` stays in the raw tier. Each operation kind has a maturity per environment, `test` until an operator moves it to `production` (`POST /operator/operation-kinds/{kind}/maturity`, with a change reason), stored as append-only config entries with who and when and audited as an admin task; one operator moves it back to test the same way, and asking for the maturity it already has changes nothing. Each model endpoint may have a processor record (`PUT /operator/model-endpoints/{id}/processor-record`: the data processing agreement, sub-processors with locations, provider-side retention, and `acceptsUnmaskedInput` with a reason). All of it is operator-only and audited. The gate target carries the kind's maturity, whether the call is synthetic, whether the endpoint has a processor record and whether it accepts unmasked input, and the gate, told the environment tier, refuses a kind in test except for a synthetic call in a test environment (`maturity`), a real-data call to an endpoint without a processor record (`processor`), and media unless the endpoint accepts unmasked input (`media`). Publishing a service refuses a `call-operation` step, in its flow or a subflow it reaches, on a descriptor in review, a kind not in production here, a model that is not the service's or outside its residency, or an endpoint without a processor record; the gate checks the same at every call, so a kind moved back to test stops the service at its next call. The step runs under the service's guardrails, masking, metering and audit like any call, and `gate@1` runs the described port as a lane of its own.
- Built (#297): the nightly retention purge deletes each day of the outside-run log once the day is older than the tenant's audit period (`retention.auditDays`, the platform default when the tenant sets none), with the day's content key. Other tenants' logs and the current day are never touched.
- Not built yet: `acceptsUnmaskedInput` is recorded on the endpoint's processor record, not yet in the service's confirmed risk assessment as the decision says; the processor record bars only described calls, not typed ones such as chat, so an endpoint without one still serves chat; the before- and after-model hooks do not see a described call; the executor runs unary calls only, so a descriptor may declare its stream events but is not streamed or proven on them yet; a descriptor declares no checks beyond its shapes, so `openai/decide@1` does not check that the answers match the questions as the hand-written adapter does; no console view of descriptors, maturity, processor records or the raw tier yet. Image input to `decide` is refused like any media, the gate counts no bytes, and the outside-run log is not in the portal's usage figures (#305). That a service without `decidesAboutPeople` only decides about content is declared, not checked.
