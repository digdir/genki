# 0047 One governed path for model operations

Status: proposed, 2026-11-03 (gate as a wrapper and payload guard in the gate built, 2026-11-03; operations on the catalogue and `decide` built, 2026-11-03; closed payload shapes, the gate as the only governed path and calls outside a run built, 2026-11-03; operation descriptors, the executor, `operation@1` and the raw tier built, 2026-11-03; the described tier, maturity per kind and processor records built, 2026-11-03; the outside-run log's retention built, 2026-11-03; one-operator promotion, 2026-11-03; three ways round the gate closed, 2026-11-03; new kinds from a descriptor alone and the last checks on `call-operation` built, 2026-11-04; descriptors reviewed in genki, uploaded by an operator without a deploy, 2026-11-04; the endpoint protocol, the `descriptors` opt-in and ids that name the kind amended by [ADR 0048](0048-connections-serve-many-apis.md), and "Kept out" replaced by [ADR 0049](0049-any-provider-api-through-descriptors.md), 2026-11-05; the gate order, `apis` in place of `operations`, prices per request and per image, and the console's API tab corrected to match the code, 2026-11-05)

Left: byte counts in `kernel.gate.call` and the outside-run log in the usage figures (#305); the before- and after-model hooks on descriptor calls (#323); the principal on outside-run audit records (#324); a processor record for typed calls with real data (#325, partly built by ADR 0048: typed chat and decide calls carry the connection's record and `GENAI_PROCESSOR_RECORDS=enforce` refuses real data without one); unmasked image, audio and file input on the service's confirmed risk assessment (#326); streaming descriptor calls and their stream events (#302); usage fields per descriptor that price image and audio tokens apart from text tokens (#314); media blobs deleted with their run's retention (#343); recorded fixtures from a live provider for each bundled descriptor (#313, the live run on genki-test records them); unknown answer fields counted on the hand-written adapters (#317); `gate@1` covering every port and kind, with the remaining mutants (#327). The status turns `accepted` after the live proof on genki-test.

## Context

Model providers add a new kind of API every month or two: decisions, image, speech, realtime, batch, provider-side files and agents. Genki reaches models through three separate stacks (`port-model`, `port-embedding`, `port-rerank`), each with its own router, and the governance in them already differs: only the model router checks lockdown admission (ADR 0033), rerank meters nothing, the embedding router has no egress guard and no tenant sharing, and search embeddings outside a run are metered into a no-op. PII masking and hooks wrap only the port named `model` (`packages/guardrails/src/strategy.ts`, `packages/hooks/src/strategy.ts`), so a new port would skip them without anyone noticing. Issue #248 (the Azure OpenAI Decisions API) is the first new kind that needs a decision.

## Decision

### One gate

Every model call passes through one gate in the kernel, `packages/kernel/src/gate.ts`, whatever its kind. The gate does, in this order and nothing else: admission, enabled, tenant sharing, every residency ceiling (router, request, service), the payload guard on the request, the call through the egress-guarded fetch, usage into the meter, media output kept as a blob of the run, provenance, the audit event `kernel.gate.call` (port, operation, model, endpoint, status, the bytes of media output, never the body; other byte counts are left, #305), then the guard on the result. The three routers call the gate; their own copies of these checks are removed. Each port declares its admission explicitly instead of having none by accident: embeddings are `open`, as ADR 0033 intends, and rerank is admitted like chat.

### The payload guard moves into the gate

The PII vault and the before- and after-model hooks are handed to the gate as a `guard` on every `use`, not wrapped around one port by name; the hooks do not see descriptor calls yet (#323). A call whose payload has image, audio or file content is refused; letting it through on the service's confirmed risk assessment is left (#326).

### Closed payload shapes

Every operation declares a closed payload shape (`packages/kernel/src/payload.ts`): where text, images, audio, files, ids and usage sit in the request, the response and the stream events. No field takes anything: `json` is a declared JSON value that only a `typed` descriptor may use in its input or wire request, and `opaque` is replay state that only an adapter declares. One walker uses the shape to mask, restore, find media and validate:

- an unknown field in a request is refused before anything leaves Genki;
- an unknown field in a response is dropped and counted in the audit event (on descriptor calls and `decide`; on the other hand-written adapters, #317);
- an unknown stream event ends the stream (descriptors are not streamed yet, #302);
- a URL in a request field that is not text, or a provider-side object id in an identifier, is refused; a URL inside text stays allowed.
- media is a field class of its own, `media` with one media type: in a request it is refused as media input; in a result the gate decodes it, counts its bytes, refuses it whole when it is over the cap for its type, and keeps it as a blob of the run, so the result holds a reference and never the bytes.

### Operations on the catalogue

A catalogue model binds one API per operation kind it serves under `apis`, next to `capabilities` ([ADR 0048](0048-connections-serve-many-apis.md)): the built-in kinds `chat` and `decide` and any kind a registered API defines; a binding to an API that does not exist is refused. An operator classifies the APIs a deployment serves, as ADR 0044 prefers evidence to guessing from names. An adapter implements the operations it supports; a call to one it does not implement fails as `unsupported` (ADR 0023). The first new operation is `decide` (#248), exposed as the kernel port `decision` over the same routes, so grants, `use:decision` policy and the audit event come from the kernel.

### Descriptors and three tiers

A new kind can arrive without hand-written types through an operation descriptor: a versioned file with the endpoint path, the payload shape, the usage mapping and the stream events, keyed on the API version and any beta headers. Descriptors are reviewed in genki and proven against fixtures in the contract suite `operation@1` (fixtures recorded from a live provider are #313). An operator uploads a descriptor with its recorded fixtures through the operator API; the same loader rules and `operation@1`, with the masking probe, run on the upload before it is stored, and every upload, status change and withdrawal is audited with who, when and why. A descriptor is data and holds no code, so a new one needs no deploy. The bundled folder is the starting set and changes through a pull request. A version is never edited once something may depend on it: a bundled descriptor or a described upload is followed by a new version, not replaced. A descriptor's id names its API (`<provider>/<api>@<version>`) and its `operation` field names its kind (ADR 0048), and loading refuses one whose input could reach the model field or the path, and one that declares stream events (#302). One executor turns a descriptor into a gated call and sets the model field to the catalogue deployment, so a caller cannot pick another deployment. A service may name a model used only for one kind (`spec.model.operations`), with the same grants and checks as its other models. New media kinds come from descriptors alone: a descriptor marks an output field `{ media: <type/subtype> }`, the deployment's configuration says which media types are kept and the cap for each, and no platform code names a media type; storage, the timeline, the answer's `attachments` and the route that serves the bytes do not depend on it.

| Tier                      | Who may call                                                                   | Guard                                                                 |
| ------------------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| Raw: descriptor in review | Operators, as a kernel task, synthetic data, test only                         | All PII categories masked always, media refused, admitted logins only |
| Described                 | Services, through a `call-operation` step block, once the kind is `production` | The service's own guardrails                                          |
| Typed                     | Services and strategies through Genki's own types                              | The service's own guardrails                                          |

A raw use that a service depends on becomes described or typed before the service may publish it.

A descriptor cannot switch the gate off through its field classes. A `plain` request field refuses a URL, a `data:` URL and a run of more than 64 base64 characters, for every gated call. A descriptor that is not `typed` may not declare `json` in its input or wire request, and `operation@1` puts a valid synthetic national id, an email and a phone number into every input string and fails if any reaches the wire unmasked; only a `typed` descriptor, whose shapes are Genki's own, may send `plain` or `ref` input. A descriptor call is refused unless the catalogue model binds the descriptor as its API for the descriptor's kind.

### What a descriptor call must meet before it carries real data

These rules cover descriptor calls, raw and described. Typed calls, drafts and ingestion are governed by ADR 0033 and ADR 0044; a processor record for typed calls is #325, partly built by ADR 0048 for typed chat and decide calls.

1. It runs inside a published service version, or it is an operator call marked synthetic. Anything else, such as a draft in the builder or the playground, is refused.
2. The endpoint's residency is within the service's at publish and at call, and the endpoint has a processor record: its data processing agreement, sub-processors with locations, and provider-side retention. An endpoint without one cannot serve a service with real data.
3. Every text field is masked by the service's PII guardrail, which publish requires for a `call-operation` step, and the raw tier masks every category. Image, audio and file input is refused; letting it through when the service's confirmed risk assessment records it with reasons is left (#326).
4. Every call is audited as who, what, where and how much (the principal on outside-run records is #324); the payload is kept only in the encrypted store under the service's retention.
5. Each operation kind has a maturity for its descriptor calls, `test` or `production`; typed calls of the built-in kinds are production by construction. The environment declares its tier, and the gate refuses an operation whose maturity does not admit it, at publish and at call. One operator moves a kind to `production` or back to `test`, audited with who, when and the change reason.

### Decisions about people

A service whose decisions concern a natural person declares `decidesAboutPeople`. That requires the risk class `high`, a human step before a result is final, and the model input kept for review. A refusal or a low-confidence answer goes to a person, never to "no"; `decide` is served to services only through `purpose-check`, so a `call-operation` step on `decide` is refused at publish. Without the declaration, a decision may only concern content; the service declares this, and Genki does not check it.

### Kept out

Replaced by [ADR 0049](0049-any-provider-api-through-descriptors.md), 2026-11-05. The text below is what held until then.

Realtime and live sessions, ephemeral provider keys in the browser, batch, provider-side files, vector stores and conversations, stored or background responses, hosted agents and tools, voice cloning and URLs the provider fetches do not go through descriptors. Each needs its own ADR, because each holds a session or keeps data at the provider, which conflicts with ADR 0044 and ADR 0045.

## Why

The three routers already disagree on governance, and each new kind built the same way would add a fourth copy that fails open where it is missed. Gateways that moved fast on decisions (LiteLLM, GoModel, LLM Gateway) were fast because auth, cost and logging sat in one place; what they added per kind was the shape. A closed shape, unlike a list of paths to mask, proves that the rest of a request carries no user content, so the raw lane can mask and meter instead of passing bodies through unread.

One operator, not two, moves a kind to production. The gate still refuses a real-data call without a processor record and keeps the raw tier to test with synthetic data, every change is audited with a reason and one operator can reverse it, and in a small team a second confirmer becomes a formality.

Uploads, not only pull requests, because a descriptor holds no code: the loader rules and `operation@1` are the review that matters, and they run the same on upload as in CI. The tiers still decide what an uploaded descriptor may reach, and one operator, audited, moves it out of review.

Turned down:

- A port per family with its own router and catalogue: it duplicates the deployment and the governance, and drifts.
- Opaque pass-through: it cannot mask, guard or reliably meter.
- An external gateway as the way in for new kinds: residency hides behind one URL, it adds a processor, and new kinds still wait for the gateway.
- JSONPath or the providers' OpenAPI specs as the descriptor language: paths locate text but do not prove the rest is harmless, and specs lag new features.
- Media scanning as a substitute for a recorded decision: it is not reliable enough to stand in for one.

## Consequences

- The gate ships as a wrapper around the existing routers first, behind two contract suites, `gate@1` and `operation@1`; the routers' own checks are removed only when the suites pass. CI enumerates every registered operation and descriptor, so a new one cannot ship unproven. The key test: "no operation sends a valid national id upstream when the service masks national ids", checked against the recorded request bodies.
- Moving the guard into the gate changes masking for every service run and must not mask twice.
- Rerank becomes metered, and embeddings get the egress guard and tenant sharing.
- The masker covers patterns for Norwegian ids, phone, email, account numbers and ICD-10 codes, not names or free-text health data. Masking reduces exposure; it does not make data anonymous.
- A new host, or a partner model sold under its own terms, may be a new sub-processor that agencies must be told about before their data reaches it. In production that notice, not the code, sets how fast a new kind can go live.
- Built (#277): `packages/kernel/src/gate.ts`, as a wrapper the model, embedding and rerank routers call, and the contract suite `gate@1` (`packages/kernel/src/gate-contract.ts`), run against the bare gate and against the three routers. The gate checks admission, enabled, tenant sharing and every residency ceiling, refuses image, audio and file content, masks and runs the guards, calls, meters, records provenance and writes `kernel.gate.call`; the egress guard stays in each endpoint's fetch. The PII vault and the model hooks are handed to it on every `use` (`UseOptions.guards`), and the service's residency with them. Embeddings and rerank have optional `tenants` in their catalogs. Rerank is metered as one request per call.
- Built (#248): catalogue models bind one API per kind under `apis` (ADR 0048), set in the catalogue or by an operator (`PATCH /operator/models/{id}`), and a call to a kind a model does not bind, or its adapter does not implement, fails as `unsupported`. `decide` is the kernel port `decision`, served by the model router (`ModelRouter.decisions()`) over the same catalogue, implemented in `openai-chat` against `/openai/v1/decisions`, with Genki's own types (`packages/port-model/src/decision.ts`). Its payload was the first closed shape; the adapter keeps only the documented response fields of the wire answer and counts the rest in `kernel.gate.call` as `dropped`. `decision` is a lane in `gate@1`, so the national id test covers it. `decidesAboutPeople` is checked at publish: risk class `high`, the `human-approval` guardrail as the human step, and no `pii-out-of-log`, since the run's input under the service's retention (at least 183 days for `high`) is what keeps the model input for review. The guardrail `purpose-check` is the first use; a refusal or an answer below its threshold interrupts the run for a person, or lets it through when the service says so, and is never a refusal. Decisions show in the run timeline and in the eval observation.
- Built (#290): `packages/kernel/src/payload.ts` holds the closed shapes of chat, decide, embed and rerank as the ports have them, and one walker that masks, restores, finds media and validates. The gate refuses a request outside its shape (`shape`) before and after the guards, refuses a URL or a provider object id in an identifier, drops an unknown answer field and counts it as `dropped`, and ends a stream on an unknown event. Text fields alone are masked; a URL inside text stays allowed. The replay state in `continuation` is not open: each adapter declares its shape (`ModelAdapter.continuation`), and the chat shape allows only those. The routers keep only routing: admission, enabled, sharing and residency are checked in the gate alone, so a refusal now comes when the call is made, not when the port is opened. `gate@1` checks the shapes and provenance, and runs against mutated gates that each leave one check out, which must fail. Adapters get their fetch from the gate (`Gate.egress`), which applies the endpoint's egress guard on every request. The before- and after-model hooks run on `decide` with the input text and the answers, and operators see the kinds a model serves in the console and in the admin MCP's `list_models`, and set its `apis` in the console (ADR 0048).
- Built (#291): descriptors are YAML files in `packages/operations/descriptors/<provider>/<operation>@<version>.yaml`, data and never code, so a descriptor can only say what the one executor does. Each names its API version and the query and headers it is keyed on, the endpoint path relative to the catalogue endpoint, the typed input and output and the wire request and response in the vocabulary of `payload.ts`, a declarative mapping between them (`$input`, `$response` and `$deployment` paths, `$from`, `$default`, `$omitWhen`, `$each`, `$sort`, `$map`), the usage mapping and its stream events or `none`. Loading refuses a URL, a credential header, a path to a kept-out API and a wire field such as `store` or `previous_response_id`; a `typed` descriptor must declare the shapes Genki has for its operation. The executor (`describedCall`, `packages/operations/src/executor.ts`) runs through the gate with the descriptor's own shapes, builds the wire body from the masked input, sets the model to the catalogue deployment, refuses a body outside the wire shape, sends with the endpoint's credential through the gate's egress fetch, drops and counts unknown answer fields and meters the mapped usage; `kernel.gate.call` names the descriptor.
