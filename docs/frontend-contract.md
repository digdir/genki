# Frontend contract

Status: stable for the server kind. Everything under Calls, Citations and sources and Streaming is checked by the platform's own contract suite (see Contract tests). Changes are additive. Pin the service version with `GenAI-Version` so a service change does not move under your frontend.

Still preview: the `browser` kind (tested with a test token, not against live Ansattporten), and the live run of the suite against a deployed platform, which is opt-in and not part of CI.

New to this? Start with [Build a frontend](build-a-frontend.md): the three sources to read, in order, and the shortest call sequence.

This page is what the platform expects from a frontend that is not the portal, and what it promises in return. The contract is the OpenAI-compatible `/v1` API with the extensions below. MCP (`/api/mcp`) stays for agents, tools and headless-rag compatibility; a frontend does not need it.

## What we expect

1. Register the frontend in the portal: open the service, go to **Kanaler og frontend**, then **Egne brukerflater**, then **Registrer brukerflate**. Choose the channels it may call (`openai`, `conversations`, `facets`, `feedback`), and its kind: `server` (calls from your own server with an API key) or `browser` (signs in with Ansattporten and calls the platform with the user's token; needs the client id, redirect URIs and allowed origins).
2. Call only the platform. Never call the search engine or a model provider directly, and never ship a key that can read or write the search engine or administer the platform. A frontend holds, at most, one API key bound to its service, and only on a server.
3. Show answers as they are: every answer is generated by AI (`ai_generated`, header `genai-generated-by: ai`). Mark it so in the UI.
4. Resolve citations only with the rule below. Do not number sources yourself.
5. Show a service, then its variants. Never present a variant as a separate service or agent (see Services and their variants).

## Auth

| Frontend kind | Credential                                                                                       | Notes                                                                                                                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Server        | `X-API-Key: <key>` (or `Authorization: Bearer <key>`), plus `X-User-Id: <pseudonymous end user>` | Create the key under the service in the portal ("API-nøkler for tjenesten"); bind it to the registered frontend so its channels and origins apply. See Who owns a conversation, and Feedback, for what the key and `X-User-Id` decide. |
| Browser       | `Authorization: Bearer <Ansattporten token>`, optionally `GenAI-Acting-For: <org number>`        | For frontends registered as `browser`. CORS is answered for the allowed origins only. Verified in tests with a test principal and token; not exercised against live Ansattporten in this repo.                                         |

Rate limits apply per key. `401` means no or bad credentials, `403` a key that may not reach the service, channel or dataset.

## Calls

| Need                                        | Call                                                                                                            |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| List services the credential may use        | `GET /v1/models`                                                                                                |
| One service's input form and output shape   | `GET /v1/models/{id}/schema` (JSON Schema, see Services and their forms)                                        |
| Ask, whole answer                           | `POST /v1/chat/completions`                                                                                     |
| Ask, streamed                               | same with `"stream": true` (and `"genai_stream": "live"`)                                                       |
| Conversations                               | `GET/POST /api/conversations`, `GET/PUT/DELETE /api/conversations/{id}`                                         |
| Datasets a service searches, with filters   | `_datasets` on `GET /v1/models` (see Datasets and filters)                                                      |
| Datasets and the filter fields they declare | `GET /api/datasets`, `GET /api/datasets/{id}`                                                                   |
| Facet values to build filters               | `GET /api/facets?tenant=&dataset-config-key=&fields=a,b&filter=<json>`                                          |
| Feedback                                    | `POST /api/feedback` with `{ "task": "<genai-task header>", "rating": "up" or "down", "comment"?, "reasons"? }` |

OpenAPI: the platform document is served at `/openapi.json`; the per-key tool document is at `/api/tools/openapi.json`. The `/v1` routes follow OpenAI's own schema, and the extensions are the fields listed here.

Send `GenAI-Version: <n>` to run a published version of the service, or put `"metadata": { "version": "<n>" }` in the body of `POST /v1/chat/completions`. If both are sent they must name the same version, or the call fails with `400 invalid_version`; a version that was never published is `409 version_not_found`. The response carries `genai-service-version`. Per channel: `/v1/chat/completions` reads the header and `metadata.version`; REST `/api/tools/call/{tool}` and MCP `tools/call` read the header; A2A takes no pin and runs the published version, which its agent card names.

## Services and their forms

`GET /v1/models` lists only what the credential may use: a service key sees its own service, a tenant key its tenant's services, a browser token what the person may reach. Each entry is an OpenAI model object (`id`, `object`, `created`, `owned_by`) with these extension fields. Apart from `_chat` and `_pickable`, absent fields are left out, so treat them as optional.

| Field            | Type                              | Meaning                                                                                                                                                                                                                                                                                                                                                   |
| ---------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | string                            | The name to send as `model`. Format `<service>__<variant>`, for example `klarsprak__default`.                                                                                                                                                                                                                                                             |
| `title`          | string                            | Display name of the service (variants add their own name). A variant title the service gives in both languages follows `Accept-Language` (`nb` or `en`); the service name itself is the author's text in the language it was written.                                                                                                                     |
| `description`    | string                            | The service's purpose, as plain text for any caller. The author's text, not translated.                                                                                                                                                                                                                                                                   |
| `_service`       | string                            | The service id, the same on every row of the service. Group rows by this field.                                                                                                                                                                                                                                                                           |
| `_service_title` | string                            | The service name, the same on every row of the service. Draw the service with this.                                                                                                                                                                                                                                                                       |
| `_variant`       | string                            | The variant id within the service: `default`, `retrieve-only` or a name the service defines.                                                                                                                                                                                                                                                              |
| `_variant_title` | string                            | The variant name only, following `Accept-Language` (`nb` or `en`). Draw the variant with this.                                                                                                                                                                                                                                                            |
| `_pickable`      | boolean                           | Always present. `true` when an end user may pick this row in a chat or variant picker: a chat variant of a service exposed for chat, not paused and not an alias.                                                                                                                                                                                         |
| `_alias_of`      | string                            | On an alias row only: the `id` the alias points to. Skip these rows in lists and pickers.                                                                                                                                                                                                                                                                 |
| `_agent_id`      | string                            | Same as `_service`, kept for headless-rag compatibility. Accepted as `agent` in the conversation routes.                                                                                                                                                                                                                                                  |
| `_mode`          | string                            | Same as `_variant`, kept for headless-rag compatibility.                                                                                                                                                                                                                                                                                                  |
| `_default`       | `true`                            | Present on the service's default variant.                                                                                                                                                                                                                                                                                                                 |
| `_chat`          | boolean                           | Always present. `true` on the one entry per service that belongs in a chat list (the service has `exposure.chat` and this is its first variant under its public name); `false` everywhere else, including form services and aliases. To list every service once, keep entries with `_default: true`; a chat-only screen can narrow that to `_chat: true`. |
| `_batch`         | `true`                            | On a `_chat` entry whose service has batch runs enabled: the same questions over many rows or documents (`/api/batch-runs`).                                                                                                                                                                                                                              |
| `input_fields`   | array of field objects            | The service's input form. Absent when the service has no form. See below.                                                                                                                                                                                                                                                                                 |
| `_datasets`      | array                             | The datasets the service searches: `[{ id, tenant, "dataset-config-key", filters: [{ field, kinds, "value-type" }] }]`. Absent when the service searches none; such a service refuses `filters`. See Datasets and filters.                                                                                                                                |
| `_documents`     | `{accepts, max_bytes, max_count}` | The service takes attached documents; see Attached documents.                                                                                                                                                                                                                                                                                             |
| `status`         | `"paused"`                        | Present only when the service is paused. Do not offer it; calls answer `503 service_paused`.                                                                                                                                                                                                                                                              |
| `status_reason`  | string                            | Why it is paused, in text suitable for the user.                                                                                                                                                                                                                                                                                                          |

### input_fields

Each field object has:

| Key           | Type                                                                                    | Meaning                                                                                                                                                                                                                                           |
| ------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | string, `^[a-z][a-zA-Z0-9_]{0,63}$`                                                     | The key in the `input` object.                                                                                                                                                                                                                    |
| `label`       | string                                                                                  | The label, in the language the service author wrote it.                                                                                                                                                                                           |
| `kind`        | `text`, `long-text`, `choice`, `multi-choice`, `number`, `year`, `date`, `organisation` | Value type. `text` is a string up to 2000 characters, `long-text` up to 20000. `choice` and `organisation` are one string, `multi-choice` a list of strings. `year` is an integer from 1800 to 2200, `date` is `YYYY-MM-DD`, `number` any number. |
| `required`    | boolean                                                                                 | Must be filled in (a `default` counts as filled).                                                                                                                                                                                                 |
| `help`        | string                                                                                  | Help text for the field.                                                                                                                                                                                                                          |
| `options`     | string[]                                                                                | The allowed values for `choice`, `multi-choice` and `organisation`. When the service draws them from a dataset (`optionsFrom`), the platform has already filled `options` with the current values, most frequent first (at most 500).             |
| `optionsFrom` | `{dataset, facet, min?, max?, pattern?}`                                                | Where the options come from. Informational; use `options`.                                                                                                                                                                                        |
| `default`     | string, number or string[]                                                              | Used when the field is left blank.                                                                                                                                                                                                                |
| `dependsOn`   | string                                                                                  | The id of another field this one depends on, for UIs that narrow one choice by another.                                                                                                                                                           |

Send the values as `"input": { "<id>": value }` in `POST /v1/chat/completions`, with an optional free-text question as the last user message. A missing required field or a value outside its options answers `400` with `code: "invalid_input"` and `errors: [{ "path": "<id>", "message": "…" }]`; the messages are Norwegian. A service with a form may be called with `input` alone: `messages` can be left out or empty, and the run gets no question. Every run needs something to work from: at least one filled field or a question. A form whose fields are all optional and left empty, sent with no question, is `invalid_input` with `errors: [{ "path": "query", "message": "Fyll ut skjemaet eller skriv et spørsmål." }]`; this holds for every output kind, tables included. Show it next to the question box. A service without a form still answers `400 missing_messages` for empty `messages`. Leave out a field the person did not fill in rather than sending `""`: the schema marks text fields `minLength: 1`, so an empty string is refused even when the field is optional. Numbers and years may be sent as numeric strings; a `multi-choice` may be sent as one string.

### The schema of one service

`GET /v1/models/{id}/schema` returns the same form, and the shape of the result, as JSON Schema 2020-12. Use the same credential and `{id}` as in `/v1/models`. When the service searches datasets, the response also carries `datasets`, the same list as `_datasets` on `/v1/models`. An id the credential cannot see answers `404 model_not_found`; no credential answers `401`. It belongs to the `openai` channel, so a key or client registered for that channel may read it.

```json
{
  "id": "maloppnaelse__default",
  "title": "Vurdering av måloppnåelse",
  "x-label": { "nb": "Vurdering av måloppnåelse", "en": "Vurdering av måloppnåelse" },
  "input": {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "type": "object",
    "required": ["ministry", "year"],
    "x-label": { "nb": "Skjema", "en": "Form" },
    "properties": {
      "ministry": {
        "type": "string",
        "enum": ["Kunnskapsdepartementet", "Finansdepartementet"],
        "x-label": { "nb": "Departement", "en": "Departement" },
        "x-widget": "select",
        "x-options": { "enum": ["Kunnskapsdepartementet", "Finansdepartementet"] },
        "x-order": 0
      },
      "year": {
        "type": "integer",
        "minimum": 1800,
        "maximum": 2200,
        "x-label": { "nb": "År", "en": "År" },
        "x-widget": "number",
        "x-order": 1
      },
      "topics": {
        "type": "array",
        "items": { "type": "string", "enum": ["Digitalisering", "Klima"] },
        "x-label": { "nb": "Tema", "en": "Tema" },
        "x-widget": "multiselect",
        "x-options": { "enum": ["Digitalisering", "Klima"] },
        "x-order": 2
      }
    }
  },
  "output": {
    "$schema": "…",
    "type": "string",
    "x-kind": "answer",
    "x-carriedIn": "choices[0].message.content",
    "x-label": { "nb": "Svar", "en": "Answer" }
  }
}
```

- `input` validates the `input` object of the chat request: it accepts and rejects the same values as the API. It carries `x-label`, `x-help`, `x-widget`, `x-options` and `x-order`: `x-order` is the display order, `x-options.enum` the values to offer, and `x-widget` and `x-label` are described below. Field labels and help are the service author's own text, so both languages hold the same string; the form title and output labels are translated.
- `x-widget` is one of `text`, `textarea`, `prompt`, `number`, `toggle`, `select`, `multiselect`, `model`, `dataset`, `tool`, `secret`, `cron`, `code`, `list`, `map`; draw an unknown value as a text field. `x-label`, `x-help` and `x-group` are `{ "nb": "…", "en": "…" }` without `Accept-Language` and a plain string with it.
- A `multi-choice` field is `type: "array"` with the allowed values under `items.enum` (and in `x-options.enum`), drawn as `x-widget: "multiselect"`; send a list of strings. A `choice` field is `type: "string"` with `enum`, drawn as `select`.
- `output` describes the result by the service's output kind. `answer` and `document`: a string in `choices[0].message.content`. `fields`: an object with one typed property per field, labelled with the field's label from the service definition (the key when it has none), delivered as JSON text in the message content (on `/api/tools/call/{tool}` as `fields`). Every field is present; a field the definition marks `required: false` is not in `required` and may be `null` when the document does not have it. `table`: `{ columns: [{ key, label }], rows: [{ document?, cells: { <key>: { value, sources } } }] }`, where `value` has the column's type, delivered as the response's `table` member (and `csv`). `x-kind` and `x-carriedIn` name the kind and where it arrives.
- A table cell's `sources` are the source objects behind that cell, not references to the response's `sources`: `{ chunk_id, document_id?, title?, url?, excerpt?, position?, published_at? }`, with `url` only when it opens (http or https). They carry no `index`, because a cell has no `[N]` markers; show them as that cell's sources. The camelCase keys `chunkId`, `document` and `publishedAt` are also present, for older clients.
- `Accept-Language: nb` or `en` resolves every `x-label`, `x-help` and `x-group` to one string; without it both are returned as `{nb, en}`. The response varies on `Accept-Language`.
- `GET /schemas` and `GET /schemas/{kind}@{version}` publish the schemas for configuring services; the per-service schema above is the one to build a user screen from.

## Asking

Request (everything except `model` and `messages` is optional):

```json
{
  "model": "kunnskapsassistenten__default",
  "messages": [{ "role": "user", "content": "Hva sier evalueringene om digital veiledning?" }],
  "conversation_id": "…",
  "genai_conversation": true,
  "filters": {
    "fields": [
      { "field": "concerned_years", "value-type": "integer", "selected-options": [2024, 2025] }
    ]
  },
  "tenant": "digdir",
  "dataset_config_key": "kudos",
  "stream": true,
  "genai_stream": "live",
  "genai_steps": true
}
```

A plain OpenAI client that sends none of the extensions gets stateless behaviour, as before.

### Services and their variants

A service can have several variants: other ways to use the same service, such as a faster model or a fixed step flow ("annual reports first"). A variant shares its service's purpose, data, rules and access. The rule for a frontend:

- **Show the service, then its variants. Never present a variant as a separate service or agent.**
- List one entry per service: the row with `_default: true`, drawn with `_service_title`.
- Group rows by `_service`. Skip rows with `_alias_of` and rows with `status: "paused"`.
- If a service has more than one `_pickable` row, offer them as a secondary choice, a variant picker labelled with `_variant_title`. Preselect the `_default` row. With one `_pickable` row, show no picker.
- Send the chosen row's `id` as `model`. A conversation keeps its service; the variant can change from one question to the next.
- `title` is kept for older clients and its format depends on the credential; draw with `_service_title` and `_variant_title` instead.
- The owner chooses which variants end users can pick ("Kan velges i chat" in the portal, `variants[].chat` in the definition); `_pickable` follows it.
- A2A agent cards carry the same rule in their name: "Service · Variant", and the default variant's card is named after the service alone.

A variant picker, in outline:

```ts
const rows = (await (await fetch('/v1/models', { headers })).json()).data;
const services = new Map<string, { title: string; variants: typeof rows }>();
for (const row of rows) {
  if (row._alias_of || row.status === 'paused') continue;
  const service = row._service ?? row._agent_id;
  const entry = services.get(service) ?? { title: row._service_title ?? row.title, variants: [] };
  if (row._pickable) entry.variants.push(row);
  services.set(service, entry);
}
// For each service: show entry.title; if entry.variants.length > 1, show a picker
// with variant._variant_title, preselecting the row where _default is true.
```

Older platforms without `_pickable` can fall back to `_chat || _default`.

### Conversations

- `genai_conversation: true` creates a conversation. `conversation_id: "<id>"` continues one. Either way the platform stores the user turn and, after a successful run, the assistant turn with its sources, and the response carries `conversation_id` (body, first stream frame, and the `genai-conversation` header).
- With a conversation the platform loads the history itself. Send only the new user message; earlier turns in `messages` are ignored.
- An unknown or foreign id answers `404` with code `conversation_not_found`. A failed run stores no assistant turn.
- A request that fails before the run starts (any `400`, `403`, `404`, `409` or `503` answer) creates no conversation, so `genai_conversation: true` on a refused request leaves nothing behind. A run that fails without streaming (`500`) removes the conversation it just created. A streamed run has already announced its id; it keeps the user turn and no assistant turn.
- The conversation routes (`/api/conversations`) list, read, rename and delete the same conversations. A new conversation is titled from the first line of its first question (60 characters); until then its `topic` is the default.

Shapes:

| Call                             | Body                                                           | Answer                                                                        |
| -------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `GET /api/conversations`         | query `page_size` (1 to 100, default 50), `page_index`, `tags` | `{ conversations: [Conversation], total, pageSize, pageIndex }`, newest first |
| `POST /api/conversations`        | `{ "service"?, "title"?, "tags"? }`                            | `201 { conversation: Conversation }`                                          |
| `GET /api/conversations/{id}`    |                                                                | `{ conversation: Conversation, messages: [Message] }`                         |
| `PUT /api/conversations/{id}`    | `{ "title"?, "topic"?, "tags"? }`                              | `{ conversation: Conversation }`                                              |
| `DELETE /api/conversations/{id}` |                                                                | `{ success: true }`                                                           |

- `service` is a service id or a model `id`; `agent` and `agent-id` are accepted for headless-rag compatibility.
- `Conversation` is `{ id, topic, serviceId, agentId, userId, tags, created }`; `agentId` is the same as `serviceId`, kept for compatibility; `created` is milliseconds since 1970.
- `Message` is `{ id, role, text, created, tags, filterValue, chunks, sources?, task?, attachments?, input? }`. `role` is `user` or `assistant`; system prompts are never returned. On a user message, `input` holds the form values and `attachments` the attached file names. On an assistant message, `sources` are the sources as the answer gave them (`{ index?, title, url?, document_id?, excerpts }`, the same shape and rule as Citations and sources, so `[N]` in `text` is the source with `index: N`), and `task` is the id for feedback. `chunks` (`[{ chunkId, docTitle, docNum, contentMarkdown }]`) is the older per-chunk list, kept for headless-rag clients; use `sources`. Messages stored before `sources` existed have only `chunks`.
- `PUT` treats `title` and `topic` as the same field. Any other key answers `400 unknown_field`.

### Who owns a conversation

- A key bound to one service (a service key) serves end users: send `X-User-Id` and each end user sees only their own conversations. Without `X-User-Id` the key itself owns them.
- Any other credential owns its conversations itself. A tenant key ignores `X-User-Id`: every conversation made with that key is in one shared list, and `userId` is the key's own id. Use a service key when a frontend serves several people.
- A browser token owns the conversations of the person signed in.

### Attached documents

- A service takes documents with the question when `GET /v1/models` shows `_documents` on it: `accepts` (the media types this service takes), `max_bytes` (2 MiB) and `max_count` (5). `_documents.accepts` is authoritative; offer only those types. The platform can read `text/plain`, `text/markdown`, `text/csv` and `application/json`, and each service picks its own subset.
- Send them as `genai_documents: [{ "name": "brev.md", "media_type": "text/markdown", "data": "<base64>" }]` on `POST /v1/chat/completions`. Errors: `400 invalid_documents`, `400 documents_not_accepted`, `413 document_too_large`, `415 unsupported_document_type`. A request body over 16 MiB is refused with `413 request_too_large`; `/api/tools/call/{tool}` takes at most 1 MiB.
- Every strategy that answers from sources uses them: the RAG strategies and the agent loop give an attached document to the model as the first numbered sources, before the search results, and they are cited like other sources (`title` is the file name, `document_id` and chunk ids start with `attached:`). Such a source has no `url` and no entry in `citations`, since there is nothing to open. Plain chat gets the text in the prompt.
- With a conversation, the user turn stores the file names, and `GET /api/conversations/{id}` returns them as `attachments` on that message. The `task` id for feedback is on the assistant message that answers it. The file content is not repeated in later turns; attach it again to ask about it again.
- The files are kept in tenant blob storage. Files sent with a conversation are deleted right away when the conversation is deleted (`DELETE /api/conversations/{id}`); otherwise the nightly retention job deletes them when the service's retention period has passed.

### Datasets and filters

Start from the service. `_datasets` on its `/v1/models` entry (and `datasets` in its schema) lists every dataset it searches:

```json
{
  "id": "rapporter",
  "tenant": "digdir",
  "dataset-config-key": "rapporter",
  "filters": [
    { "field": "year", "kinds": ["multiselect"], "value-type": "integer" },
    { "field": "organisation", "kinds": ["multiselect"], "value-type": "string" }
  ]
}
```

- `tenant` is the dataset's owner, which may differ from the tenant of your key. Pass it, and `dataset-config-key`, to `/api/facets`. `dataset-config-key` is the dataset id; both are listed so you never derive one from the other.
- `kinds` are the filter kinds the dataset allows for the field: `select`, `multiselect`, `text`, `range`, `boolean`.
- `value-type` is `string` or `integer`. Facet values always arrive as strings; for an `integer` field send the chosen values as numbers with `"value-type": "integer"`.
- A service without `_datasets` searches no dataset and refuses `filters` with `400 invalid_filters`.

`GET /api/facets?tenant=<tenant>&dataset-config-key=<key>&fields=year,organisation&filter=<json>` returns `{ "fields": [{ "field": "year", "options": [{ "value": "2024", "count": 3, "selected": false }] }] }`. Options are sorted by value. With `filter`, each field's counts follow the other fields' selections, and `selected` marks what `filter` chose (disjunctive facets). `403 dataset_not_authorized` means the credential may not read that dataset; `400 invalid_request` a missing parameter or a bad `filter`.

Send the chosen values with the question as `filters`: `{ "fields": [{ "field", "type"?: "multiselect" | "contains" | "not-in-set", "value-type"?: "string" | "integer", "selected-options": [...] }] }`, the same shape as the `filter` parameter of `/api/facets`. A bad shape, or a field the service's datasets do not declare, answers `400` with code `invalid_filters` and `errors: [{ "path": "filters.fields[0].field", "message": "…" }]`. Do not combine `filters` with `overrides.retrieve-filter-by`. `tenant` and `dataset_config_key` in the ask body are optional; when sent they must name one of the service's datasets, or the call answers `403 dataset_not_authorized`.

`GET /api/datasets` lists the datasets the credential may read: `{ "datasets": [{ "id", "tenant", "name", "description", "enabled?", "status" }] }`. `GET /api/datasets/{id}` returns one: `{ "dataset": { "id", "tenant", "name", "description", "enabled?", "status", "filters": [{ "field", "kinds", "value-type" }] } }`. Both shapes, and the key `enabled?` (always `true`), are kept as headless-rag served them. `status` is how the platform fills the dataset:

| `status`         | Meaning for a frontend                                                                  |
| ---------------- | --------------------------------------------------------------------------------------- |
| `ready`          | Filled by the platform, last run succeeded.                                             |
| `running`        | A fill is running now.                                                                  |
| `configured`     | A fill is set up but has not finished yet.                                              |
| `degraded`       | The last fill failed; the content may be old or incomplete.                             |
| `external`       | Filled outside the platform (for example an existing search index). Searchable.         |
| `needs-pipeline` | The platform has no fill for it. It may be empty, or loaded by hand; do not rely on it. |

### Citations and sources

`[N]` in the answer text always refers to the source with `index: N`. Each source is one document:

```json
{
  "index": 1,
  "title": "Tildelingsbrev 2025",
  "url": "https://kudos.dfo.no/dokument/d1",
  "document_id": "d1",
  "excerpts": [
    { "chunk_id": "c1", "text": "…", "position": 0 },
    { "chunk_id": "c7", "text": "…", "position": 4 }
  ]
}
```

- `url` is present only when the platform's public link rule gives an http or https link people can open. Never build a link from `document_id`.
- `excerpts` holds every retrieved chunk of that document, so a frontend never fetches passage text itself. Per-chunk ids are `excerpts[].chunk_id`.
- Existing fields (`source`, `document`, `metadata`, `excerpt`) are kept for OpenAI and Open WebUI clients. Note that `document` there is still the list of passage texts, which is why the document id is `document_id`. The top-level `citations` lists only links people can open, so it does not line up with `sources`; resolve `[N]` by `index`, never by position in `citations`.
- An answer without citations still lists up to 10 retrieved sources, one per document, without `index`.
- No answer: `no_answer: true` and a `notice` text to show instead of the answer.

### Errors

- `/v1/*` answers OpenAI's shape: `{ "error": { "message", "type", "code", "param" } }`, plus `errors: [{ path, message }]` for `invalid_input` and `invalid_filters`.
- `/api/*` (conversations, feedback, datasets, facets, tools) answers `application/problem+json`: `{ "type", "title", "status", "detail", "code", "errors"? }`. The same body also carries `error` with the message text, for older clients.
- Show `detail` or `message` to the person, and use `code` to decide; never parse the text.

### Streaming

Default (`"stream": true`): sources first, then the whole answer once, then `[DONE]`. With `"genai_stream": "live"` the answer arrives as token deltas; when the platform replaces a draft it sends a frame with `"retract": true`, and the client drops what it showed so far and starts again from the next text. Sources follow the text in live mode. `"genai_steps": true` adds frames with a `genai_step` object (`event`, `stage`, `label`, `tool`, `iteration`, `max-iterations`, `duration-ms`, `tool-calls`) so a UI can show progress. Every member is optional, but a step frame always has at least one; which ones depend on the service's strategy. A run that fails inside the stream ends with `finish_reason: "error"` and an `error` object. Keep-alive comments (`: keep-alive`) are sent while the model works.

Frames in order for a live stream with a conversation (each line is `data: <json>`, shortened):

```
{"object":"chat.completion.chunk","choices":[{"delta":{"role":"assistant"}}],"conversation_id":"c-1"}
{"choices":[{"delta":{"content":"Rapporten "}}]}
{"choices":[{"delta":{"content":"sier [1] at"}}]}
{"choices":[{"delta":{}}],"retract":true}
{"choices":[{"delta":{"content":"Rapporten sier [1] at ..."}}]}
{"choices":[{"delta":{}}],"citations":["https://..."],"sources":[{"index":1,"title":"...","url":"..."}]}
{"choices":[{"delta":{},"finish_reason":"stop"}]}
[DONE]
```

Without `genai_stream: "live"` the `sources` frame comes before the text and there is no `retract`. A table service sends one frame with `table` before the text. `genai_steps: true` adds `{"genai_step":{...}}` frames between text frames.

Response headers: `genai-task` (use it for feedback), `genai-conversation`, `genai-service-version`, `genai-model`.

### Feedback

`POST /api/feedback` with `{ "task": "<genai-task>", "rating": "up" | "down", "comment"?, "reasons"? }` answers `201 { "ok": true, "task": "<task>" }`. The platform takes feedback on a run only from the credential that made it: the same API key, or the same signed-in person. `X-User-Id` plays no part, so your server should send feedback only for task ids it got for that end user. Another key answers `403` with `errors: [{ "path": "task" }]`; an unknown task `404`. Comments are stored with personal data masked.

## Use the client (repository only)

For contributors with the repository. `@genai/client` (`packages/client`) is not published to a package registry yet; a frontend outside the repository uses the HTTP calls above, which is all the client does. It wraps all of this, has no runtime dependencies and works in Node and browsers.

```ts
import { createClient, selection, citedIndexes, sourceFor } from '@genai/client';

const platform = createClient({
  baseUrl: 'https://platform.example.no',
  apiKey: process.env.PLATFORM_KEY, // server only
  userId: 'pseudonym-123',
  version: 4, // optional pin
});

const services = await platform.listServices();

let shown = '';
const answer = await platform.ask(
  {
    service: 'kunnskapsassistenten__default',
    question: 'Hva sier evalueringene om digital veiledning?',
    newConversation: true,
    filters: { fields: [selection('concerned_years', [2024, 2025])] },
  },
  {
    onText: (t) => (shown += t),
    onRetract: () => (shown = ''),
    onStep: (step) => console.log(step.event, step.tool),
  },
);

for (const n of citedIndexes(answer.text)) {
  const source = sourceFor(answer.sources, n)!;
  console.log(
    `[${n}]`,
    source.title,
    source.url,
    source.excerpts.map((e) => e.chunkId),
  );
}

await platform.ask({
  service: 'kunnskapsassistenten__default',
  question: 'Og for 2025?',
  conversationId: answer.conversationId!,
});
await platform.conversations.list();
await platform.facets({ tenant: 'digdir', datasetConfigKey: 'kudos', fields: ['orgs_short'] });
await platform.feedback({ taskId: answer.taskId!, rating: 'up' });
```

`platform.stream(request, { steps: true })` returns an async iterator of `conversation`, `text`, `retract`, `step`, `reasoning`, `sources` and `done` events. Errors are `ApiError` with `status`, `code` and `fieldErrors`. In a browser, pass `token: () => getAnsattportenToken()` instead of `apiKey`.

## Connect Kunnskapsassistenten to genki-test

genki-test is locked (ADR 0033), so a server key reaches a model there only when a trusted Entra login created it.

1. Log in to the portal at `https://portal.genki-test.digdir.cloud` with Entra ID, not TestID.
2. Open the service `kunnskapsassistenten`, go to "API-nøkler for tjenesten" and create a key. Copy it now; it is shown once.
3. Give the key to KA test's backend as a secret, with the base URL `https://api.genki-test.digdir.cloud`, and call `POST /v1/chat/completions` with `"model": "kunnskapsassistenten"`.

Answers with sources need the Typesense search key in test: the Key Vault secret `typesense-key` must be set. A key created before this rule, or rotated by someone without an Entra login, is refused with `urn:genai:problem:locked-environment`; create a new one.
